[`parse`](/trackparse/reference/parse/), [`parseArtists`](/trackparse/reference/functions/#parseartistsinput-options) and [`createParser`](/trackparse/reference/functions/#createparseroptions) take the same options. JavaScript takes an object,
Python takes keyword arguments, Rust takes a `ParseOptions` value through the `_with` functions,
and Go takes a `ParseOptions` struct through the `With` functions.

## Parse options

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```ts
interface ParseOptions {
  mode?: "auto" | "clean" | "youtube" | "filename" | "tracklist";
  knownArtists?: string[];
  uploader?: string;
  splitAnd?: "auto" | "always" | "never";
  keywords?: KeywordOptions;
}
```

</TabItem>
<TabItem label="Python">

```python
parse(
    input,
    *,
    mode: ModeOption = "auto",       # "auto" | "clean" | "youtube" | "filename" | "tracklist"
    known_artists: Sequence[str] = (),
    uploader: Optional[str] = None,
    split_and: str = "auto",         # "auto" | "always" | "never"
    keywords: Optional[KeywordOptions] = None,
)
```

</TabItem>

```rust
#[non_exhaustive]
pub struct ParseOptions {
    pub mode: ModeOption,                   // Auto | Clean | Youtube | Filename | Tracklist
    pub uploader: Option<String>,
    pub known_artists: Vec<String>,
    pub split_and: SplitAnd,                // Auto | Always | Never
```

Start from the defaults and chain a setter per option
([`ParseOptions` on docs.rs](https://docs.rs/trackparse/latest/trackparse/struct.ParseOptions.html)):

```rust
use trackparse::{parse_with, ModeOption, ParseOptions, SplitAnd};

let input = "Chase & Status - Baddadan";
let options = ParseOptions::new()
    .mode(ModeOption::Youtube)
    .known_artists(["Chase & Status"])
    .uploader("Daft Punk - Topic")
    .split_and(SplitAnd::Never);
&parse_with(input, &options).artists[0].name;   // "Chase & Status"
```

</TabItem>
<TabItem label="Go">

```go
type ParseOptions struct {
	Mode         Mode       // ModeAuto | ModeClean | ModeYouTube | ModeFilename | ModeTracklist; "" means auto
	Uploader     string     // empty means none
	KnownArtists []string
	SplitAnd     SplitAnd   // SplitAndAuto | SplitAndAlways | SplitAndNever; "" means auto
```

Set the fields you need. The others keep their zero value, which is the default
([`ParseOptions` on pkg.go.dev](https://pkg.go.dev/github.com/4matic/trackparse/go#ParseOptions)):

```go
import (
	"fmt"

	"github.com/4matic/trackparse/go"
)

input := "Chase & Status - Baddadan"
options := trackparse.ParseOptions{
	Mode:         trackparse.ModeYouTube,
	KnownArtists: []string{"Chase & Status"},
	Uploader:     "Daft Punk - Topic",
	SplitAnd:     trackparse.SplitAndNever,
}
fmt.Printf("%q\n", trackparse.ParseWith(input, options).Artists[0].Name)   // "Chase & Status"
```

| JavaScript | Python and Rust | Go | Default | |
|---|---|---|---|---|
| `mode` | `mode` | `Mode` | `"auto"` | Which [mode](/trackparse/guides/modes/) to use. `auto` picks `filename`, `youtube` or `clean` from the string |
| `knownArtists` | `known_artists` | `KnownArtists` | empty | Names that are never split, like `Chase & Status` or `Earth, Wind & Fire`. Matched case- and accent-insensitively. See [knownArtists](/trackparse/guides/artists/#knownartists) |
| `uploader` | `uploader` | `Uploader` | none | The YouTube channel. In youtube mode it becomes the artist when there's no separator. `- Topic` and `VEVO` are dropped. See [the uploader fallback](/trackparse/guides/modes/#the-uploader-fallback) |
| `splitAnd` | `split_and` | `SplitAnd` | `"auto"` | `auto` splits on `and` only after a comma (`A, B and C`), so `Simon and Garfunkel` stays whole. `always` and `never` do what they say. See [`and` is special](/trackparse/guides/artists/#and-is-special) |
| `keywords` | `keywords` | `Keywords` | none | Extra vocabulary, see [keywords](#keywords) below |

All five work the same in [`parse`](/trackparse/reference/parse/),
[`parseArtists`](/trackparse/reference/functions/#parseartistsinput-options) (which ignores `mode`
and `uploader`) and [`createParser`](/trackparse/reference/functions/#createparseroptions). The
playground has a field for each but `keywords`:
[this link](/trackparse/playground/#track=Chase%20%26%20Status%20-%20Baddadan&mode=youtube&splitAnd=never&known=Chase%20%26%20Status&uploader=Daft%20Punk%20-%20Topic) opens the example above with all four set.

In Rust the values are enums: [`ModeOption`](https://docs.rs/trackparse/latest/trackparse/enum.ModeOption.html)`::Auto`, `Clean`,
`Youtube`, `Filename` or `Tracklist`, and [`SplitAnd`](https://docs.rs/trackparse/latest/trackparse/enum.SplitAnd.html)`::Auto`, `Always`
or `Never`. The option structs are `#[non_exhaustive]`, so start
from `ParseOptions::new()` (or `default()`) and chain setters. The fields are public and can also
be assigned.

In Go the values are typed strings with constants: [`trackparse.ModeAuto`](https://pkg.go.dev/github.com/4matic/trackparse/go#ModeAuto),
`ModeClean`, `ModeYouTube`, `ModeFilename` or `ModeTracklist` (the type [`Mode`](https://pkg.go.dev/github.com/4matic/trackparse/go#Mode)), and
`SplitAndAuto`, `SplitAndAlways` or `SplitAndNever` (the type [`SplitAnd`](https://pkg.go.dev/github.com/4matic/trackparse/go#SplitAnd)). The zero
value of `ParseOptions` is the defaults: an empty `Mode` is auto, an empty `SplitAnd` is auto and an
empty `Uploader` is none. A string that is not one of the constants behaves as an unknown value does
in JavaScript.

Options never cause an error. An unknown mode, a `knownArtists` that isn't a list or a keyword of
the wrong type is ignored and the default is used. In Rust and Go the options are typed, so most of
those values can't be written at all. The option rules are
[R12](/trackparse/reference/spec/#r12-options) in the spec.

In Python the options can also travel as a dict, typed as the `ParseOptions` `TypedDict`:
`parse(s, **options)`. In Rust with the `serde` feature, `ParseOptions` reads from JSON with the
JavaScript key names (`{"mode":"youtube","knownArtists":["Chase & Status"]}`). Reading is strict:
a missing key is the default, an unknown name such as `"mode":"radio"` is an error.

## keywords

`keywords` adds words to the built-in vocabulary. It can't take any away. In Python its keys are
snake_case too: `version_heads`, `feat_markers`. In Rust,
[`KeywordOptions`](https://docs.rs/trackparse/latest/trackparse/struct.KeywordOptions.html) has one setter per word, and each call adds one
entry. In Go, [`Keywords`](https://pkg.go.dev/github.com/4matic/trackparse/go#Keywords) holds slices: the two maps of the JavaScript options
are ordered slices of [`VersionHead`](https://pkg.go.dev/github.com/4matic/trackparse/go#VersionHead) and [`JunkPhrase`](https://pkg.go.dev/github.com/4matic/trackparse/go#JunkPhrase), because a Go map has no insertion order. They
are read as JavaScript reads an object: a repeated key keeps its first place and takes the last
value, and integer-like keys come first, in ascending order. The built-in lists are JSON files in
[`spec/data`](https://github.com/4matic/trackparse/tree/main/spec/data), and the keyword rules are
[R12](/trackparse/reference/spec/#r12-options). [Your own words](/trackparse/guides/versions/#your-own-words) in the
versions guide has another example.

<TabItem label="JavaScript">

```ts
interface KeywordOptions {
  versionHeads?: Record<string, VersionType>;   // { rerub: "rework" }
  descriptors?: string[];                        // extra style words, like the built-in "D'n'B"
  genres?: string[];                             // extra genre names (junk kind 'genre')
  junk?: Record<string, JunkKind>;               // { "live stream": "other" }
  featMarkers?: string[];                        // extra feat markers
}
```

```python
    genres: list[str]                       # extra genre names (junk kind 'genre')
    junk: dict[str, JunkKind]               # {"live stream": "other"}
    feat_markers: list[str]                 # extra feat markers
```

Keys are compared the same way as the built-in words: ASCII letters are lowercased and one trailing
`. , ! ? : ;` is ignored.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { createParser } from "trackparse";

const parser = createParser({
  knownArtists: ["Chase & Status", "Camo & Krooked"],
  keywords: { versionHeads: { rerub: "rework" } },

const t = parser.parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)");
t.artists.map((a) => a.name);   // [ 'Chase & Status', 'Camo & Krooked' ]
t.versions[0].type;             // 'rework'
```

A junk phrase works the same way. Without the keyword the bracket stays in the title, because
nothing recognizes it:

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { parse } from "trackparse";

parse("Artist - Song [Some Label Rip]").title;   // 'Song [Some Label Rip]'

const r = parse("Artist - Song [Some Label Rip]", { keywords: { junk: { "some label rip": "label" } } });
r.title;   // 'Song'
r.junk;    // [ { raw: 'Some Label Rip', kind: 'label' } ]
```

</TabItem>
<TabItem label="Python">

```python
from trackparse import parse

parse("Artist - Song [Some Label Rip]").title   # 'Song [Some Label Rip]'

r = parse("Artist - Song [Some Label Rip]", keywords={"junk": {"some label rip": "label"}})
r.title   # 'Song'
r.junk    # (Junk(raw='Some Label Rip', kind='label'),)
```

</TabItem>
<TabItem label="Rust">

```rust
use trackparse::{parse, parse_with, JunkKind, KeywordOptions, ParseOptions};

parse("Artist - Song [Some Label Rip]").title;   // "Song [Some Label Rip]"

let keywords = KeywordOptions::new().junk("some label rip", JunkKind::Label);
let r = parse_with("Artist - Song [Some Label Rip]", &ParseOptions::new().keywords(keywords));
&r.title;   // "Song"
&r.junk;    // [Junk { raw: "Some Label Rip", kind: Label }]
```

</TabItem>
<TabItem label="Go">

```go
fmt.Printf("%q\n", trackparse.Parse("Artist - Song [Some Label Rip]").Title)   // "Song [Some Label Rip]"

keywords := trackparse.Keywords{
	Junk: []trackparse.JunkPhrase{{Phrase: "some label rip", Kind: trackparse.JunkKindLabel}},
}
r := trackparse.ParseWith("Artist - Song [Some Label Rip]", trackparse.ParseOptions{Keywords: keywords})
fmt.Printf("%q\n", r.Title)   // "Song"
fmt.Printf("%+v\n", r.Junk)   // [{Raw:Some Label Rip Kind:label}]
```

## Tracklist options

[`parseTracklist`](/trackparse/reference/tracklist/#parsetracklisttext-options) and [`applyEdits`](/trackparse/reference/tracklist/#applyeditstext-edits-options) (`parse_tracklist` and `apply_edits` in Python and Rust,
`ParseTracklist` and `ApplyEdits` in Go) take
`mode` (default `"tracklist"`), [`knownArtists`](/trackparse/guides/artists/#knownartists), [`splitAnd`](/trackparse/guides/artists/#and-is-special) and `keywords`, plus two of their own.
In Rust they are the setters of [`TracklistOptions`](/trackparse/reference/tracklist/#options), passed to `parse_tracklist_with` and
`apply_edits_with` ([`TracklistOptions` on docs.rs](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.TracklistOptions.html)).
In Go they are the fields of the [`TracklistOptions`](https://pkg.go.dev/github.com/4matic/trackparse/go#TracklistOptions) struct, passed to
[`ParseTracklistWith`](https://pkg.go.dev/github.com/4matic/trackparse/go#ParseTracklistWith) and [`ApplyEditsWith`](https://pkg.go.dev/github.com/4matic/trackparse/go#ApplyEditsWith). The
rules are [R13.10](/trackparse/reference/spec/#r1310-options):

| JavaScript | Python and Rust | Go | Default | Description |
|---|---|---|---|---|
| [`audioSeconds`](/trackparse/guides/tracklists/#options) | `audio_seconds` | `AudioSeconds` | none | Length of the audio. Turns on the [`time-after-audio-end`](/trackparse/reference/warnings/#tracklist-warnings:~:text=time%2Dafter%2Daudio%2Dend) check |
| [`markerWords`](/trackparse/guides/tracklists/#options) | `marker_words` | `MarkerWords` | empty | Extra marker words. With `["drop"]`, `03:00 Drop` is a marker, not a track |

In Go the zero value of `TracklistOptions` is the defaults too: an empty `Mode` means
`ModeTracklist`, and `ModeAuto` asks for auto mode on each line. `AudioSeconds` is a `*float64`,
so `nil` means no length and [`trackparse.Ptr`](https://pkg.go.dev/github.com/4matic/trackparse/go#Ptr)`(0.0)` is an audio of length 0, as `audioSeconds: 0`
is in JavaScript.

[Tracklists](/trackparse/guides/tracklists/#options) has an example in each language, and the
[Tracklist API](/trackparse/reference/tracklist/#options) lists them again with the functions.

## Format options

[`format`](/trackparse/reference/functions/#formattrack-options) has its own options (`feat`, [`featMarker`](/trackparse/guides/formatting/#options), `joiners`, `versions`, `producers`, `position`).
They are listed under [Formatting](/trackparse/guides/formatting/#options). In Go they are the
fields of [`FormatOptions`](https://pkg.go.dev/github.com/4matic/trackparse/go#FormatOptions); `producers: false` is `OmitProducers: true` there, so the zero value
keeps the producers, and `FeatMarker` is a `*string` (`nil` keeps the input's marker). In Rust
they are the setters of [`FormatOptions`](https://docs.rs/trackparse/latest/trackparse/struct.FormatOptions.html). The rules are
[R11](/trackparse/reference/spec/#r11-format).
