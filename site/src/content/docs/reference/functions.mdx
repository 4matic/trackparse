All of these are exported from `trackparse`. The Python package and the Rust crate have the same
functions in snake_case, and the Go package in CamelCase. [`parse`](/trackparse/reference/parse/) and the
[tracklist functions](/trackparse/reference/tracklist/) have pages of their own.

| JavaScript | Python | Rust | Go |
|---|---|---|---|
| `parse` | `parse` | `parse`, `parse_with` | `Parse`, `ParseWith` |
| `parseArtists` | `parse_artists` | `parse_artists`, `parse_artists_with` | `ParseArtists`, `ParseArtistsWith` |
| `format` | `format_track` | `format_track`, `format_track_with` | `Format`, `FormatWith` |
| `normalize` | `normalize` | `normalize` | `Normalize` |
| `allArtists` | `all_artists` | `all_artists` | `AllArtists` |
| `createParser` | `create_parser` | `Parser::new` | `NewParser` |
| `SPEC_VERSION` | `SPEC_VERSION` | `SPEC_VERSION` | `SpecVersion` |
| `parseTracklist`, `applyEdits` (from `trackparse/tracklist`) | `parse_tracklist`, `apply_edits` (from `trackparse.tracklist`) | `parse_tracklist`, `parse_tracklist_with`, `apply_edits`, `apply_edits_with` (from `trackparse::tracklist`) | `ParseTracklist`, `ParseTracklistWith`, `ApplyEdits`, `ApplyEditsWith` (same package) |

What to know for each language:

- **JavaScript.** Options are one object, the last argument. No function throws on a string.
  The tracklist functions are in the separate entry `trackparse/tracklist`.
- **Python.** Options are keyword arguments, and fields are snake_case attributes (`full_title`,
  `unknown_artist`). Every function that takes a string raises `TypeError` if the input isn't a
  `str`. `format_track` and `all_artists` take a `ParsedTrack` and don't check it, so a wrong value
  fails with `AttributeError`. Anything else, bad options included, falls back to defaults.
- **Rust.** There are no optional arguments, so each function that takes options comes in two
  forms. The plain one uses the defaults, and the `_with` one takes a reference to an options
  struct (`parse_with(input, &options)`). Inputs are `&str`, fields are snake_case, results are
  returned by value with no `Result`, and no function panics. The signatures are on
  [docs.rs](https://docs.rs/trackparse).
- **Go.** Like Rust, each function that takes options comes in two forms: `Parse(input)` and
  `ParseWith(input, options)`. Options are structs passed by value, and their zero value means the
  defaults. Fields are exported CamelCase (`FullTitle`, `UnknownArtist`), nullable fields are
  pointers, and results are returned by value with no `error`. No function panics, and input that
  is not valid UTF-8 is read with U+FFFD in place of each bad sequence. The tracklist functions
  are in the same package.

The options themselves are on the [Options](/trackparse/reference/options/) page.

## parseArtists(input, options?)

*(Python and Rust: `parse_artists`, Go: `ParseArtists`)*

Splits a bare artist string, with no title, into credits.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { allArtists, format, normalize, parse, parseArtists } from "trackparse";

parseArtists("Sub Focus, Wilkinson & Dimension feat. Kojo").map((a) => `${a.name}:${a.role}`);
// [ 'Sub Focus:primary', 'Wilkinson:primary', 'Dimension:primary', 'Kojo:featured' ]
```

</TabItem>
<TabItem label="Python">

```python
from trackparse import all_artists, format_track, normalize, parse, parse_artists

[f"{a.name}:{a.role}" for a in parse_artists("Sub Focus, Wilkinson & Dimension feat. Kojo")]
# ['Sub Focus:primary', 'Wilkinson:primary', 'Dimension:primary', 'Kojo:featured']
```

</TabItem>
<TabItem label="Rust">

```rust
use trackparse::{all_artists, format_track_with, normalize, parse, parse_artists};
use trackparse::{FeatPlacement, FormatOptions, JoinerStyle};

parse_artists("Sub Focus, Wilkinson & Dimension feat. Kojo")
    .iter().map(|a| format!("{}:{}", a.name, a.role)).collect::<Vec<_>>();
// ["Sub Focus:primary", "Wilkinson:primary", "Dimension:primary", "Kojo:featured"]
```

</TabItem>
<TabItem label="Go">

```go
import (
    "fmt"

    "github.com/4matic/trackparse/go"
)

for _, a := range trackparse.ParseArtists("Sub Focus, Wilkinson & Dimension feat. Kojo") {
    fmt.Printf("%s:%s\n", a.Name, a.Role)
}
// Sub Focus:primary
// Wilkinson:primary
// Dimension:primary
// Kojo:featured
```

</TabItem>
</Tabs>

Takes `knownArtists`, `splitAnd` and `keywords` (`known_artists`, `split_and`, `keywords`; in Rust
through `parse_artists_with`, in Go through `ParseArtistsWith`). Use it for the artist field of ID3 tags or a streaming API, where
the title is already separate. The result is a list of
[`Artist`](/trackparse/reference/parse/#artist) values, and the splitting rules are explained in
[Artists and credits](/trackparse/guides/artists/). In the spec this is
[R10](/trackparse/reference/spec/#r10-parseartists).

## format(track, options?)

*(Python and Rust: `format_track`, Go: `Format`)*

Renders a `ParsedTrack` back to a string. Junk is left out.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
format(parse("Wilkinson ft. Becky Hill - Afterglow (Sub Focus Remix)"), { feat: "title", joiners: "canonical" });
// 'Wilkinson - Afterglow (feat. Becky Hill) (Sub Focus Remix)'
```

</TabItem>
<TabItem label="Python">

```python
format_track(parse("Wilkinson ft. Becky Hill - Afterglow (Sub Focus Remix)"), feat="title", joiners="canonical")
# 'Wilkinson - Afterglow (feat. Becky Hill) (Sub Focus Remix)'
```

</TabItem>
<TabItem label="Rust">

```rust
let options = FormatOptions::new().feat(FeatPlacement::Title).joiners(JoinerStyle::Canonical);
format_track_with(&parse("Wilkinson ft. Becky Hill - Afterglow (Sub Focus Remix)"), &options);
// "Wilkinson - Afterglow (feat. Becky Hill) (Sub Focus Remix)"
```

</TabItem>
<TabItem label="Go">

```go
options := trackparse.FormatOptions{Feat: trackparse.FeatTitle, Joiners: trackparse.JoinersCanonical}
fmt.Printf("%q\n", trackparse.FormatWith(trackparse.Parse("Wilkinson ft. Becky Hill - Afterglow (Sub Focus Remix)"), options))
// "Wilkinson - Afterglow (feat. Becky Hill) (Sub Focus Remix)"
```

</TabItem>
</Tabs>

The options are `feat`, `featMarker` (`feat_marker`), `joiners`, `versions`, `producers` and
`position`. In Go they are the fields of `FormatOptions`, where `OmitProducers: true` stands for
`producers: false`. [Formatting](/trackparse/guides/formatting/) has the table and an example of each. In
the spec this is [R11](/trackparse/reference/spec/#r11-format).

## normalize(input)

The Unicode cleanup every function runs first. It applies NFC, removes invisible characters
(zero-width spaces, BOMs, soft hyphens), turns dash, bracket and quote variants into their plain
ASCII forms, and collapses whitespace.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
normalize("Noisia​ — “Stigma”");   // 'Noisia - "Stigma"'
```

</TabItem>
<TabItem label="Python">

```python
normalize("Noisia\u200b — “Stigma”")   # 'Noisia - "Stigma"'
```

</TabItem>
<TabItem label="Rust">

```rust
normalize("Noisia\u{200b} — “Stigma”");   // "Noisia - \"Stigma\""
```

</TabItem>
<TabItem label="Go">

```go
fmt.Printf("%q\n", trackparse.Normalize("Noisia\u200b — “Stigma”"))   // "Noisia - \"Stigma\""
```

</TabItem>
</Tabs>

You don't need to call it before `parse`. It's exported because it helps when you build lookup
keys. The steps are [R1](/trackparse/reference/spec/#r1-normalization) in the spec.

## allArtists(track)

*(Python and Rust: `all_artists`, Go: `AllArtists`)*

Every credit of a track in one list: the artists, then every remixer, with duplicates removed.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
allArtists(parse("Wilkinson ft. Becky Hill - Afterglow (Sub Focus Remix)")).map((a) => `${a.name}:${a.role}`);
// [ 'Wilkinson:primary', 'Becky Hill:featured', 'Sub Focus:remixer' ]
```

</TabItem>
<TabItem label="Python">

```python
[f"{a.name}:{a.role}" for a in all_artists(parse("Wilkinson ft. Becky Hill - Afterglow (Sub Focus Remix)"))]
# ['Wilkinson:primary', 'Becky Hill:featured', 'Sub Focus:remixer']
```

</TabItem>
<TabItem label="Rust">

```rust
all_artists(&parse("Wilkinson ft. Becky Hill - Afterglow (Sub Focus Remix)"))
    .iter().map(|a| format!("{}:{}", a.name, a.role)).collect::<Vec<_>>();
// ["Wilkinson:primary", "Becky Hill:featured", "Sub Focus:remixer"]
```

</TabItem>
<TabItem label="Go">

```go
for _, a := range trackparse.AllArtists(trackparse.Parse("Wilkinson ft. Becky Hill - Afterglow (Sub Focus Remix)")) {
    fmt.Printf("%s:%s\n", a.Name, a.Role)
}
// Wilkinson:primary
// Becky Hill:featured
// Sub Focus:remixer
```

</TabItem>
</Tabs>

## createParser(options)

*(Python: `create_parser`, Rust: `Parser::new`, Go: `NewParser`)*

Compiles options and keywords once and returns an object with `parse` and `parseArtists`
(`parse_artists`). Use it when you parse many strings with the same `knownArtists` or `keywords`.

In JavaScript and Python the two methods still accept options, and per-call options are merged
over the compiled ones: `parser.parse(s, { mode: "youtube" })`, `parser.parse(s, mode="youtube")`.
The Rust `Parser` takes its options once, in `Parser::new(&options)`. Its `parse` and
`parse_artists` take only the input, and it is `Send + Sync`, so one parser can serve many threads. The Go `NewParser(options)` works
the same way: its `Parse` and `ParseArtists` methods take only the input, and a `*Parser` is safe
for concurrent use by many goroutines.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { createParser } from "trackparse";

const parser = createParser({
  knownArtists: ["Chase & Status", "Camo & Krooked"],
  keywords: { versionHeads: { rerub: "rework" } },
});

parser.parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)").versions[0].type;
// 'rework'
```

</TabItem>
<TabItem label="Python">

```python
from trackparse import create_parser

parser = create_parser(
    known_artists=["Chase & Status", "Camo & Krooked"],
    keywords={"version_heads": {"rerub": "rework"}},
)

parser.parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)").versions[0].type
# 'rework'
```

</TabItem>
<TabItem label="Rust">

```rust
use trackparse::{KeywordOptions, ParseOptions, Parser, VersionType};

let options = ParseOptions::new()
    .known_artists(["Chase & Status", "Camo & Krooked"])
    .keywords(KeywordOptions::new().version_head("rerub", VersionType::Rework));
let parser = Parser::new(&options);

parser.parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)").versions[0].version_type;
// Rework
```

</TabItem>
<TabItem label="Go">

```go
parser := trackparse.NewParser(trackparse.ParseOptions{
    KnownArtists: []string{"Chase & Status", "Camo & Krooked"},
    Keywords: trackparse.Keywords{
        VersionHeads: []trackparse.VersionHead{{Key: "rerub", Type: trackparse.VersionTypeRework}},
    },
})

fmt.Println(parser.Parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)").Versions[0].Type)
// rework
```

</TabItem>
</Tabs>

## SPEC_VERSION

The version of the [spec](/trackparse/reference/spec/) the package implements, as a string (`&str`
in Rust, the constant `SpecVersion` in Go). The packages and the spec are released together, so it's the same as the package version.
A parsed tracklist carries it too, as `specVersion` (`spec_version`).
