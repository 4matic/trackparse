Neither function fails on string input. What to know for each language:

- **JavaScript** ([`trackparse` on npm](https://www.npmjs.com/package/trackparse)). The functions live in the entry `trackparse/tracklist`, so code that only uses
  [`parse`](/trackparse/reference/parse/) never loads them. Results are plain objects, and `JSON.stringify` gives the spec's JSON.
- **Python** ([`trackparse` on PyPI](https://pypi.org/project/trackparse/)). Results are frozen dataclasses with snake_case attributes (`spec_version`,
  `first_time`) and a `to_dict()` that returns the spec's JSON shape. Edits are plain dicts with the
  same keys as in JavaScript, `"from"` included. A `text` that isn't a `str` raises `TypeError`.
- **Rust** ([`trackparse::tracklist` on docs.rs](https://docs.rs/trackparse/latest/trackparse/tracklist/index.html)). Results are structs with public snake_case fields and `to_json()`. Edits are values of
  the `Edit` enum (listed under [Types](#types)). Options go through the `_with` functions, and
  nothing panics.
- **Go** ([pkg.go.dev](https://pkg.go.dev/github.com/4matic/trackparse/go)). The functions are in the package `trackparse` itself, with no separate import. Results
  are structs with exported fields (`SpecVersion`, `FirstTime`) whose `MarshalJSON` writes the
  spec's JSON. Edits are `Edit` structs made with a constructor per edit (listed under
  [Types](#types)). Options go through the `With` functions, and nothing panics.

The guides [Tracklists](/trackparse/guides/tracklists/) and
[Editing tracklists](/trackparse/guides/editing-tracklists/) walk through examples. The rules are
[R13](/trackparse/reference/spec/#r13-tracklists) in the spec.

## parseTracklist(text, options?)

*(Python: `parse_tracklist`. Rust: [`parse_tracklist(text)`](https://docs.rs/trackparse/latest/trackparse/tracklist/fn.parse_tracklist.html) and
[`parse_tracklist_with(text, &options)`](https://docs.rs/trackparse/latest/trackparse/tracklist/fn.parse_tracklist_with.html).
Go: [`ParseTracklist(text)`](https://pkg.go.dev/github.com/4matic/trackparse/go#ParseTracklist) and [`ParseTracklistWith(text, options)`](https://pkg.go.dev/github.com/4matic/trackparse/go#ParseTracklistWith))*

Returns a `Tracklist` ([`Tracklist`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.Tracklist.html) in Rust, [`Tracklist`](https://pkg.go.dev/github.com/4matic/trackparse/go#Tracklist) in Go). Every key is
always present ([R13.8](/trackparse/reference/spec/#r138-output)). The [playground](/trackparse/playground/#list=00%3A00%20Noisia%20-%20Stigma%0A04%3A10%20Mefjus%20-%20Sleepless%20%28Phace%20Remix%29%0Aw%2F%20Phace%20-%20Psycho%20%28Acapella%29%0A09%3A30%20Outro) shows every entry of a list as a
table, with its JSON.

### TracklistEntry

One per line, in order. The table uses the JavaScript and JSON types. Python has `None` for
`null`. In Rust ([`TracklistEntry`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.TracklistEntry.html)), `line` is a `usize`, `kind` and `eol` are the
enums [`EntryKind`](https://docs.rs/trackparse/latest/trackparse/tracklist/enum.EntryKind.html) and [`Eol`](https://docs.rs/trackparse/latest/trackparse/tracklist/enum.Eol.html) (`as_str()` gives the strings below), `time` is
an `Option<TimeValue>` (a [`TimeValue`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.TimeValue.html)) whose `seconds` is an `f64`, and `track` is an
`Option<ParsedTrack>`. Go calls the type [`Entry`](https://pkg.go.dev/github.com/4matic/trackparse/go#Entry): `Kind` and `Eol` are string types
([`EntryKind`](https://pkg.go.dev/github.com/4matic/trackparse/go#EntryKind), [`Eol`](https://pkg.go.dev/github.com/4matic/trackparse/go#Eol)) whose values are the strings below, `Time` is a
[`*TracklistTime`](https://pkg.go.dev/github.com/4matic/trackparse/go#TracklistTime) whose `Seconds` is a `float64`, and `Track` is a `*Track`,
`nil` where the table says `null`.

| Field | Type | Description |
|---|---|---|
| `line` | `number` | 1-based |
| `kind` | `"track" \| "marker" \| "header" \| "link" \| "note" \| "blank"` | See [line kinds](/trackparse/guides/tracklists/#line-kinds) ([R13.3](/trackparse/reference/spec/#r133-line-kinds)) |
| `eol` | `"\n" \| "\r\n" \| "\r" \| ""` | The line's own terminator. `""` on a last line without one ([R13.1](/trackparse/reference/spec/#r131-lines-and-the-lossless-guarantee)) |
| `raw` | `string` | The line exactly as written, never normalized |
| [`parts`](/trackparse/guides/tracklists/#nothing-is-lost) | `{ lead, time, gap, rest }` | `raw` cut into four strings that join back into it ([R13.1.3](/trackparse/reference/spec/#r131-lines-and-the-lossless-guarantee:~:text=R13.1.3%20Parts)) |
| `time` | `{ raw, seconds } \| null` | The start time. See [Times](/trackparse/guides/tracklists/#times) ([R13.2](/trackparse/reference/spec/#r132-times)) |
| `track` | `ParsedTrack \| null` | Parsed from `rest` in tracklist mode, without its [Markdown emphasis](/trackparse/guides/tracklists/#markdown), a leading `w/` and a bare track number ([R13.4](/trackparse/reference/spec/#r134-the-track-part)). Only `track` and `marker` lines have one |
| `layered` | `boolean` | The track text (after any time) starts with `w/` and a space: a [layered track](/trackparse/guides/tracklists/#layered-tracks), played over the previous one ([R13.13](/trackparse/reference/spec/#r1313-layered-tracks)) |

Sorted by line ([R13.7](/trackparse/reference/spec/#r137-warnings)). The codes are listed under [Warnings](/trackparse/reference/warnings/#tracklist-warnings),
and [Suggestions](/trackparse/reference/warnings/#suggestions) explains `suggestion`. In Rust the type
is [`TracklistWarning`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.TracklistWarning.html) with a [`WarningCode`](https://docs.rs/trackparse/latest/trackparse/tracklist/enum.WarningCode.html), in Go
[`TracklistWarning`](https://pkg.go.dev/github.com/4matic/trackparse/go#TracklistWarning) with a [`WarningCode`](https://pkg.go.dev/github.com/4matic/trackparse/go#WarningCode).
Warnings from each line's own [`ParsedTrack`](/trackparse/reference/parse/#parsedtrack) stay on `entries[i].track.warnings` and aren't repeated
here.

### stats

| Field | |
|---|---|
| `lines` | number of entries |
| `tracks`, `markers` | entries of those kinds |
| `timed` | entries with a time |
| `firstTime`, `lastTime` | seconds of the first and last time, or `null` |

Python and Rust call the last two `first_time` and `last_time`. In Rust the counts are `usize` and
the two times are `Option<f64>` ([`Stats`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.Stats.html)). In Go ([`Stats`](https://pkg.go.dev/github.com/4matic/trackparse/go#Stats)) the fields are
`FirstTime` and `LastTime`, of type `*float64`.

## applyEdits(text, edits, options?)

*(Python: `apply_edits`. Rust: [`apply_edits(text, &edits)`](https://docs.rs/trackparse/latest/trackparse/tracklist/fn.apply_edits.html) and
[`apply_edits_with(text, &edits, &options)`](https://docs.rs/trackparse/latest/trackparse/tracklist/fn.apply_edits_with.html).
Go: [`ApplyEdits(text, edits)`](https://pkg.go.dev/github.com/4matic/trackparse/go#ApplyEdits) and [`ApplyEditsWith(text, edits, options)`](https://pkg.go.dev/github.com/4matic/trackparse/go#ApplyEditsWith))*

Returns `{ text, changed, warnings }` (Python, Rust and Go: an `EditResult`).

| Field | |
|---|---|
| `text` | the edited text |
| `changed` | final line numbers of every line an edit wrote, ascending |
| [`warnings`](/trackparse/reference/warnings/) | `{ code, edit, line }[]`: `edit` is the index in `edits`, `line` may be `null` |

In Rust ([`EditResult`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.EditResult.html)), `changed` is a `Vec<usize>` and each warning is an
`EditWarning { code: EditWarningCode, edit: usize, line: Option<usize> }`
([`EditWarning`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.EditWarning.html)). In Go ([`EditResult`](https://pkg.go.dev/github.com/4matic/trackparse/go#EditResult)), `Changed` is an `[]int` and each warning
is an `EditWarning{Code EditWarningCode, Edit int, Line *int}` ([`EditWarning`](https://pkg.go.dev/github.com/4matic/trackparse/go#EditWarning)). The edit rules
are [R13.9](/trackparse/reference/spec/#r139-edits).

### Edits

| JavaScript and Python | Rust | Go | Effect |
|---|---|---|---|
| `{ op: "set-time", line, seconds }` | `Edit::set_time(line, seconds)` | `SetTime(line, seconds)` | Rewrite the time on that line |
| `{ op: "shift", seconds }` | `Edit::shift(seconds)` | `Shift(seconds)` | Add `seconds` to every timed line |
| `{ op: "shift", seconds, from }` | `Edit::shift_from(seconds, from)` | `ShiftFrom(seconds, from)` | Add `seconds` to every timed line from `from` on |
| `{ op: "shift", seconds, lines }` | `Edit::shift_lines(seconds, lines)` | `ShiftLines(seconds, lines...)` | Add `seconds` to the listed lines |
| `{ op: "sort-by-time" }` | `Edit::sort_by_time()` | `SortByTime()` | Stable sort by time. Untimed lines move with the timed line above them |
| `{ op: "set-rest", line, rest }` | `Edit::set_rest(line, rest)` | `SetRest(line, rest)` | Replace everything after the time |
| `{ op: "insert", after, text }` | `Edit::insert(after, text)` | `Insert(after, text)` | Insert a line after `after` (`0` = at the top) |
| `{ op: "delete", line }` | `Edit::delete(line)` | `Delete(line)` | Remove a line |

In Python an edit is a dict with quoted keys: `{"op": "shift", "seconds": 45, "from": 5}`. With the
`serde` feature, the Rust `Edit` reads and writes that same JSON. The Go `Edit` writes it with
`json.Marshal`.

Edits run in sequence, each on the result of the one before. Times are written in their line's
style ([R13.9.2](/trackparse/reference/spec/#r139-edits:~:text=R13.9.2%20Time%20style)), up to 100 hours (or 999 minutes for lists that never use hours).
[Editing tracklists](/trackparse/guides/editing-tracklists/) has examples of each edit.

### Edit warnings

| Code | When |
|---|---|
| [`style-upgraded`](/trackparse/reference/warnings/#edit-warnings:~:text=style%2Dupgraded) | a time without hours passed one hour and gained them |
| [`time-clamped`](/trackparse/reference/warnings/#edit-warnings:~:text=time%2Dclamped) | a time would go below zero and was set to zero |
| [`edit-invalid`](/trackparse/reference/warnings/#edit-warnings:~:text=edit%2Dinvalid) | the edit could not apply and changed nothing |

In Rust the codes are [`EditWarningCode`](https://docs.rs/trackparse/latest/trackparse/tracklist/enum.EditWarningCode.html)`::StyleUpgraded`, `TimeClamped` and
`EditInvalid`. In Go they are [`EditWarningCodeStyleUpgraded`](https://pkg.go.dev/github.com/4matic/trackparse/go#EditWarningCodeStyleUpgraded), `EditWarningCodeTimeClamped` and
`EditWarningCodeEditInvalid`.
[Warnings](/trackparse/reference/warnings/#edit-warnings) shows how to check them.

## Options

Both functions take the same options ([R13.10](/trackparse/reference/spec/#r1310-options)). `applyEdits` accepts them for symmetry; edits don't depend on
them.

| JavaScript | Python and Rust | Go | Default | Description |
|---|---|---|---|---|
| `mode` | `mode` | `Mode` | `"tracklist"` | Mode for each line's [`parse()`](/trackparse/reference/parse/). See [Tracklist mode](/trackparse/guides/tracklists/#tracklist-mode) |
| [`knownArtists`](/trackparse/guides/artists/#knownartists), [`splitAnd`](/trackparse/guides/artists/#and-is-special), [`keywords`](/trackparse/reference/options/#keywords) | `known_artists`, `split_and`, `keywords` | `KnownArtists`, `SplitAnd`, `Keywords` | as for `parse` | As for [`parse()`](/trackparse/reference/options/) |
| [`audioSeconds`](/trackparse/guides/tracklists/#options) | `audio_seconds` | `AudioSeconds` | none | Length of the audio. Enables [`time-after-audio-end`](/trackparse/reference/warnings/#tracklist-warnings:~:text=time%2Dafter%2Daudio%2Dend) |
| [`markerWords`](/trackparse/guides/tracklists/#options) | `marker_words` | `MarkerWords` | empty | Extra marker words |

Python uses keyword arguments. Rust has a setter of the same name for each on [`TracklistOptions`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.TracklistOptions.html),
for example `TracklistOptions::new().audio_seconds(3600.0).marker_words(["drop"])`, and passes it
to `parse_tracklist_with` or `apply_edits_with`. Go takes a [`TracklistOptions`](https://pkg.go.dev/github.com/4matic/trackparse/go#TracklistOptions) struct, for example
`trackparse.TracklistOptions{AudioSeconds: trackparse.Ptr(3600.0), MarkerWords: []string{"drop"}}`,
in `ParseTracklistWith` or `ApplyEditsWith`. Its zero value is the defaults: an empty `Mode` means
`ModeTracklist` (`ModeAuto` asks for auto), and a `nil` `AudioSeconds` means no length, while
`trackparse.Ptr(0.0)` is an audio of length 0.
[Tracklists](/trackparse/guides/tracklists/#options) has a full example.

pub enum Edit {

<TabItem label="Go">

Everything is in the package `trackparse`: the structs `Tracklist`, `Entry`, `Parts`,
`TracklistTime`, `Suggestion`, `Stats`, `TracklistWarning`, `TracklistOptions`, `EditResult`,

```go
type Edit struct {
	Op      EditOp    // EditOpSetTime, EditOpShift, EditOpSortByTime, EditOpSetRest, EditOpInsert, EditOpDelete
	Line    int       // set-time, set-rest, delete
	Seconds float64   // set-time, shift
	Lines   []int     // shift: nil means not given
	From    *int      // shift: nil means not given
	Rest    string    // set-rest
	After   int       // insert
	Text    string    // insert
}
```

Build one with a constructor: [`trackparse.SetTime(line, seconds)`](https://pkg.go.dev/github.com/4matic/trackparse/go#SetTime), [`trackparse.Shift(seconds)`](https://pkg.go.dev/github.com/4matic/trackparse/go#Shift),

[`trackparse.Delete(line)`](https://pkg.go.dev/github.com/4matic/trackparse/go#Delete). `json.Marshal` writes an edit in the spec's JSON form.
