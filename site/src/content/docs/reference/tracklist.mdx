Neither function fails on string input. What to know for each language:

- **JavaScript.** The functions live in the entry `trackparse/tracklist`, so code that only uses
  `parse` never loads them. Results are plain objects, and `JSON.stringify` gives the spec's JSON.
- **Python.** Results are frozen dataclasses with snake_case attributes (`spec_version`,
  `first_time`) and a `to_dict()` that returns the spec's JSON shape. Edits are plain dicts with the
  same keys as in JavaScript, `"from"` included. A `text` that isn't a `str` raises `TypeError`.
- **Rust.** Results are structs with public snake_case fields and `to_json()`. Edits are values of
  the `Edit` enum (listed under [Types](#types)). Options go through the `_with` functions, and
  nothing panics.
- **Go.** The functions are in the package `trackparse` itself, with no separate import. Results
  are structs with exported fields (`SpecVersion`, `FirstTime`) whose `MarshalJSON` writes the
  spec's JSON. Edits are `Edit` structs made with a constructor per edit (listed under
  [Types](#types)). Options go through the `With` functions, and nothing panics.

The guides [Tracklists](/trackparse/guides/tracklists/) and
[Editing tracklists](/trackparse/guides/editing-tracklists/) walk through examples. The rules are
[R13](/trackparse/reference/spec/#r13-tracklists) in the spec.

### TracklistEntry

One per line, in order. The table uses the JavaScript and JSON types. Python has `None` for
`null`. In Rust, `line` is a `usize`, `kind` and `eol` are the enums `EntryKind` and `Eol`
(`as_str()` gives the strings below), `time` is an `Option<TimeValue>` whose `seconds` is an `f64`,
and `track` is an `Option<ParsedTrack>`. Go calls the type `Entry`: `Kind` and `Eol` are string
types whose values are the strings below, `Time` is a `*TracklistTime` whose `Seconds` is a
`float64`, and `Track` is a `*Track`, `nil` where the table says `null`.

| Field | Type | Description |
|---|---|---|
| `line` | `number` | 1-based |
| `kind` | `"track" \| "marker" \| "header" \| "link" \| "note" \| "blank"` | See [line kinds](/trackparse/guides/tracklists/#line-kinds) |
| `eol` | `"\n" \| "\r\n" \| "\r" \| ""` | The line's own terminator. `""` on a last line without one |
| `raw` | `string` | The line exactly as written, never normalized |
| `parts` | `{ lead, time, gap, rest }` | `raw` cut into four strings that join back into it |
| `time` | `{ raw, seconds } \| null` | The start time |
| `track` | `ParsedTrack \| null` | Parsed from `rest` in tracklist mode, without its [Markdown emphasis](/trackparse/guides/tracklists/#markdown), a leading `w/` and a bare track number. Only `track` and `marker` lines have one |
| `layered` | `boolean` | The track text (after any time) starts with `w/` and a space: a [layered track](/trackparse/guides/tracklists/#layered-tracks), played over the previous one |

Sorted by line. The codes are listed under [Warnings](/trackparse/reference/warnings/#tracklist-warnings).
Warnings from each line's own `ParsedTrack` stay on `entries[i].track.warnings` and aren't repeated
here.

### stats

| Field | |
|---|---|
| `lines` | number of entries |
| `tracks`, `markers` | entries of those kinds |
| `timed` | entries with a time |
| `firstTime`, `lastTime` | seconds of the first and last time, or `null` |

Python and Rust call the last two `first_time` and `last_time`. In Rust the counts are `usize` and
the two times are `Option<f64>`. In Go the fields are `FirstTime` and `LastTime`, of type
`*float64`.

## applyEdits(text, edits, options?)

*(Python: `apply_edits`. Rust: `apply_edits(text, &edits)` and `apply_edits_with(text, &edits, &options)`.
Go: `ApplyEdits(text, edits)` and `ApplyEditsWith(text, edits, options)`)*

Returns `{ text, changed, warnings }` (Python, Rust and Go: an `EditResult`).

| Field | |
|---|---|
| `text` | the edited text |
| `changed` | final line numbers of every line an edit wrote, ascending |
| `warnings` | `{ code, edit, line }[]`: `edit` is the index in `edits`, `line` may be `null` |

In Rust, `changed` is a `Vec<usize>` and each warning is an
`EditWarning { code: EditWarningCode, edit: usize, line: Option<usize> }`. In Go, `Changed` is an
`[]int` and each warning is an `EditWarning{Code EditWarningCode, Edit int, Line *int}`.

### Edits

| JavaScript and Python | Rust | Go | Effect |
|---|---|---|---|
| `{ op: "set-time", line, seconds }` | `Edit::set_time(line, seconds)` | `SetTime(line, seconds)` | Rewrite the time on that line |
| `{ op: "shift", seconds }` | `Edit::shift(seconds)` | `Shift(seconds)` | Add `seconds` to every timed line |
| `{ op: "shift", seconds, from }` | `Edit::shift_from(seconds, from)` | `ShiftFrom(seconds, from)` | Add `seconds` to every timed line from `from` on |
| `{ op: "shift", seconds, lines }` | `Edit::shift_lines(seconds, lines)` | `ShiftLines(seconds, lines...)` | Add `seconds` to the listed lines |
| `{ op: "sort-by-time" }` | `Edit::sort_by_time()` | `SortByTime()` | Stable sort by time. Untimed lines move with the timed line above them |
| `{ op: "set-rest", line, rest }` | `Edit::set_rest(line, rest)` | `SetRest(line, rest)` | Replace everything after the time |
| `{ op: "insert", after, text }` | `Edit::insert(after, text)` | `Insert(after, text)` | Insert a line after `after` (`0` = at the top) |
| `{ op: "delete", line }` | `Edit::delete(line)` | `Delete(line)` | Remove a line |

In Python an edit is a dict with quoted keys: `{"op": "shift", "seconds": 45, "from": 5}`. With the
`serde` feature, the Rust `Edit` reads and writes that same JSON. The Go `Edit` writes it with
`json.Marshal`.

Edits run in sequence, each on the result of the one before. Times are written in their line's
style, up to 100 hours (or 999 minutes for lists that never use hours).
[Editing tracklists](/trackparse/guides/editing-tracklists/) has examples of each edit.

### Edit warnings

| Code | When |
|---|---|
| `style-upgraded` | a time without hours passed one hour and gained them |
| `time-clamped` | a time would go below zero and was set to zero |
| `edit-invalid` | the edit could not apply and changed nothing |

In Rust the codes are `EditWarningCode::StyleUpgraded`, `TimeClamped` and `EditInvalid`. In Go
they are `EditWarningCodeStyleUpgraded`, `EditWarningCodeTimeClamped` and
`EditWarningCodeEditInvalid`.
[Warnings](/trackparse/reference/warnings/#edit-warnings) shows how to check them.

## Options

Both functions take the same options. `applyEdits` accepts them for symmetry; edits don't depend on
them.

| JavaScript | Python and Rust | Go | Default | Description |
|---|---|---|---|---|
| `mode` | `mode` | `Mode` | `"tracklist"` | Mode for each line's `parse()` |
| `knownArtists`, `splitAnd`, `keywords` | `known_artists`, `split_and`, `keywords` | `KnownArtists`, `SplitAnd`, `Keywords` | as for `parse` | As for [`parse()`](/trackparse/reference/options/) |
| `audioSeconds` | `audio_seconds` | `AudioSeconds` | none | Length of the audio. Enables `time-after-audio-end` |
| `markerWords` | `marker_words` | `MarkerWords` | empty | Extra marker words |

Python uses keyword arguments. Rust has a setter of the same name for each on `TracklistOptions`,
for example `TracklistOptions::new().audio_seconds(3600.0).marker_words(["drop"])`, and passes it
to `parse_tracklist_with` or `apply_edits_with`. Go takes a `TracklistOptions` struct, for example
`trackparse.TracklistOptions{AudioSeconds: trackparse.Ptr(3600.0), MarkerWords: []string{"drop"}}`,
in `ParseTracklistWith` or `ApplyEditsWith`. Its zero value is the defaults: an empty `Mode` means
`ModeTracklist` (`ModeAuto` asks for auto), and a `nil` `AudioSeconds` means no length, while
`trackparse.Ptr(0.0)` is an audio of length 0.
[Tracklists](/trackparse/guides/tracklists/#options) has a full example.

Exported from `trackparse::tracklist`: the structs `Tracklist`, `TracklistEntry`, `Parts`,

```rust
#[non_exhaustive]
pub enum Edit {
    SetTime { line: usize, seconds: f64 },
    Shift { seconds: f64, lines: Option<Vec<usize>>, from: Option<usize> },
    SortByTime,
    SetRest { line: usize, rest: String },
    Insert { after: usize, text: String },
    Delete { line: usize },
}
```

Each variant has a constructor: `Edit::set_time(line, seconds)`, `Edit::shift(seconds)`,
`Edit::shift_from(seconds, from)`, `Edit::shift_lines(seconds, lines)`, `Edit::sort_by_time()`,
`Edit::set_rest(line, rest)`, `Edit::insert(after, text)` and `Edit::delete(line)`.

</TabItem>
<TabItem label="Go">

Everything is in the package `trackparse`: the structs `Tracklist`, `Entry`, `Parts`,
`TracklistTime`, `Suggestion`, `Stats`, `TracklistWarning`, `TracklistOptions`, `EditResult`,
`EditWarning` and `Edit`, and the string types `EntryKind`, `Eol`, `Severity`, `WarningCode`,
`EditWarningCode` and `EditOp`, each with its constants (`EntryKindTrack`, `EolCRLF`,
`WarningCodeTimeOutOfOrder`). An edit is a struct whose `Op` says which fields it reads:

```go
type Edit struct {
    Op      EditOp    // EditOpSetTime, EditOpShift, EditOpSortByTime, EditOpSetRest, EditOpInsert, EditOpDelete
    Line    int       // set-time, set-rest, delete
    Seconds float64   // set-time, shift
    Lines   []int     // shift: nil means not given
    From    *int      // shift: nil means not given
    Rest    string    // set-rest
    After   int       // insert
    Text    string    // insert
}
```

Build one with a constructor: `trackparse.SetTime(line, seconds)`, `trackparse.Shift(seconds)`,
`trackparse.ShiftFrom(seconds, from)`, `trackparse.ShiftLines(seconds, lines...)`,
`trackparse.SortByTime()`, `trackparse.SetRest(line, rest)`, `trackparse.Insert(after, text)` and
`trackparse.Delete(line)`. `json.Marshal` writes an edit in the spec's JSON form.
