`parse` never fails on a string. Any string gives a `ParsedTrack`, the empty string included, and
unknown or malformed options fall back to their defaults. What differs between the languages:

- JavaScript: never throws on a string.
- Python: raises `TypeError` if `input` isn't a `str` (`parse() expects str input, got int`), and
  nothing else.
- Rust: takes `&str`, returns the value itself (no `Result`), and never panics. Use `parse` for the
  defaults and `parse_with` to pass options.
- Go: takes a `string`, returns the `Track` itself (no `error`), and never panics. Use `Parse` for
  the defaults and `ParseWith` to pass options. Bytes that are not valid UTF-8 are read as U+FFFD,
  one per maximal invalid sequence, as Rust's `String::from_utf8_lossy` and the browser's
  `TextDecoder` do.

The options are on the [Options](/trackparse/reference/options/) page. The other functions
(`parseArtists`, `format`, `createParser`) are under
[Other functions](/trackparse/reference/functions/), and the output model is
[defined in the spec](/trackparse/reference/spec/#output-model).

The table below uses the JavaScript and JSON names. Python has the same fields as attributes of a
frozen dataclass, in snake_case (`full_title`, `flags.unknown_artist`), with tuples instead of
arrays and `None` instead of `null`. Rust has a struct with the same snake_case names as public
fields: `Vec<T>` for arrays, `Option<T>` where the table says `null`, and enums for `mode`, roles,
kinds and warnings. Go has a `Track` struct with exported CamelCase fields (`FullTitle`,
`Flags.UnknownArtist`): slices for arrays, pointers where the table says `null`, and typed strings
for `mode`, roles, kinds and warnings.

| Field | Type | Description |
|---|---|---|
| `input` | `string` | The original string, untouched (not normalized) |
| `mode` | `"clean" \| "youtube" \| "filename" \| "tracklist"` | The mode that ran |
| `position` | `{ raw: string, number: number } \| null` | Track number. `raw` is the digits as written (`"01"`) |
| `timestamp` | `{ raw: string, seconds: number } \| null` | Leading cue time, `"1:02:03"` → 3723 |
| `artists` | `Artist[]` | Primary, featured and producer credits. Remixers are in `versions` |
| `title` | `string` | The clean title. Brackets it doesn't recognize stay in |
| `fullTitle` | `string` | `title` with the versions put back in their original brackets |
| `versions` | `Version[]` | Remixes and versions, left to right |
| `year` | `number \| null` | From `(2015)` or `- 2015` |
| `flags` | `{ explicit, clean, unknownArtist, unknownTitle }` | All booleans |
| `junk` | `{ raw: string, kind: JunkKind }[]` | What was taken out of the title, and what kind of noise it was |
| `warnings` | `Warning[]` | Which heuristics fired. See [Warnings](/trackparse/reference/warnings/) |

The guides show each field at work: [Modes](/trackparse/guides/modes/) for `mode`,
[Junk, flags and prefixes](/trackparse/guides/junk-and-flags/) for `position`, `timestamp`, `year`,
`flags` and `junk`, [Artists and credits](/trackparse/guides/artists/) for `artists`, and
[Versions and remixes](/trackparse/guides/versions/) for `versions`.

| Field | Values |
|---|---|
| `role` | `primary`, `featured`, `remixer`, `producer` |
| `joiner` | the text before the name as written (`"&"`, `","`, `"ft."`, `"prod. by"`), or `null` for the first name in a list |
| `source` | `artist` (left of the dash), `title` (right of it), `version` (inside a version) |

`&`, `x` and `vs.` are joiners, not roles. Everyone they join is `primary`. In Rust, `role` and
`source` are `ArtistRole::Primary`, `ArtistSource::Artist` and so on; in Go they are
`trackparse.RolePrimary`, `trackparse.SourceArtist` and so on.
[Artists and credits](/trackparse/guides/artists/) has examples.

</TabItem>

| Field | |
|---|---|
| `type` | one of `remix` `bootleg` `vip` `edit` `flip` `refix` `rework` `mashup` `blend` `dub` `mix` `extended` `radio` `club` `original` `instrumental` `acapella` `live` `acoustic` `remaster` `demo` `reprise` `cover` `version` `spedUp` `slowed` `nightcore` |
| `raw` | the text inside the brackets, as written |
| `artists` | remixers (role `remixer`, source `version`) |
| `modifiers` | type words that didn't become the type: `Extended VIP Mix` → `vip`, `["extended"]` |
| `descriptor` | leftover words: `"Taylor's"`, `"at Wembley"`, `"D'n'B"` |
| `year` | a year inside the version: `Remastered 2015` → 2015 |
| `unknownArtist` | `true` for `ID Remix` and the like |
| `delimiter` | the bracket it was in, or `-` for a dash suffix |

Python uses `unknown_artist`. Rust uses `unknown_artist` and `version_type`, because `type` is a
reserved word, and `delimiter` is `VersionDelimiter::Paren`, `Square`, `Curly` or `Dash`. Go uses
`Type`, `UnknownArtist` and the `Delimiter` constants `DelimiterParen`, `DelimiterSquare`,
`DelimiterCurly` and `DelimiterDash`.
[Versions and remixes](/trackparse/guides/versions/) explains how the type is chosen.

## Junk kinds

`video`, `audio`, `lyrics`, `quality`, `promo`, `platform`, `label`, `genre`, `other`. Examples are
in [Junk, flags and prefixes](/trackparse/guides/junk-and-flags/#junk). The vocabulary is in
[`spec/data`](https://github.com/4matic/trackparse/tree/main/spec/data). In Rust the kind is the
enum `JunkKind` (`JunkKind::Video` and so on), in Go the typed string `JunkKind`
(`trackparse.JunkKindVideo` and so on).

## Serializing to JSON

All four packages write the same JSON, byte for byte, on every fixture input. The keys are the
camelCase ones of the spec (`fullTitle`, `unknownArtist`), also in Python, Rust and Go.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { parse } from "trackparse";

const track = parse("Noisia - Stigma (2015)");

JSON.stringify(track);
// '{"input":"Noisia - Stigma (2015)","mode":"clean","position":null,"timestamp":null,"artists":[{"name":"Noisia","role":"primary","joiner":null,"source":"artist"}],"title":"Stigma","fullTitle":"Stigma","versions":[],"year":2015,"flags":{"explicit":false,"clean":false,"unknownArtist":false,"unknownTitle":false},"junk":[],"warnings":[]}'
```

The result is a plain object, so `JSON.stringify` is all you need, and `JSON.parse` gives the
object back.

</TabItem>
<TabItem label="Python">

```python
import json
from trackparse import ParsedTrack, parse

track = parse("Noisia - Stigma (2015)")

json.dumps(track.to_dict(), separators=(",", ":"), ensure_ascii=False)
# '{"input":"Noisia - Stigma (2015)","mode":"clean","position":null,"timestamp":null,"artists":[{"name":"Noisia","role":"primary","joiner":null,"source":"artist"}],"title":"Stigma","fullTitle":"Stigma","versions":[],"year":2015,"flags":{"explicit":false,"clean":false,"unknownArtist":false,"unknownTitle":false},"junk":[],"warnings":[]}'

ParsedTrack.from_dict(track.to_dict()) == track   # True
```

`ParsedTrack`, `Artist`, `Version`, `Junk`, `Flags`, `Position` and `Timestamp` are frozen
dataclasses. Sequences are tuples, so results are immutable and hashable: you can put them in sets
or use them as dict keys. `to_dict()` gives the spec's JSON shape as a dict, and `from_dict()` goes
the other way. The `separators` and `ensure_ascii` arguments above make `json.dumps` write the
same bytes as JavaScript.

</TabItem>
<TabItem label="Rust">

```rust
use trackparse::{parse, ParsedTrack};

let track = parse("Noisia - Stigma (2015)");

track.to_json();
// "{\"input\":\"Noisia - Stigma (2015)\",\"mode\":\"clean\",\"position\":null,\"timestamp\":null,\"artists\":[{\"name\":\"Noisia\",\"role\":\"primary\",\"joiner\":null,\"source\":\"artist\"}],\"title\":\"Stigma\",\"fullTitle\":\"Stigma\",\"versions\":[],\"year\":2015,\"flags\":{\"explicit\":false,\"clean\":false,\"unknownArtist\":false,\"unknownTitle\":false},\"junk\":[],\"warnings\":[]}"

// with the `serde` feature and serde_json:
let json = serde_json::to_string(&track).unwrap();
json == track.to_json();                                         // true
serde_json::from_str::<ParsedTrack>(&json).unwrap() == track;    // true
```

The results are plain structs that derive `Debug`, `Clone`, `PartialEq` and `Eq`. Each has
`to_json()`, which writes the spec's JSON as a compact string and needs no feature and no extra
dependency. With the optional `serde` feature (`cargo add trackparse --features serde`) the result
types, the options and the tracklist `Edit` implement `Serialize` and `Deserialize` with the same
keys, so `serde_json` writes the same text and reads it back.

</TabItem>
<TabItem label="Go">

```go
import (
    "encoding/json"
    "fmt"
    "reflect"

    "github.com/4matic/trackparse/go"
)

track := trackparse.Parse("Noisia - Stigma (2015)")

data, _ := json.Marshal(track)
fmt.Println(string(data))
// {"input":"Noisia - Stigma (2015)","mode":"clean","position":null,"timestamp":null,"artists":[{"name":"Noisia","role":"primary","joiner":null,"source":"artist"}],"title":"Stigma","fullTitle":"Stigma","versions":[],"year":2015,"flags":{"explicit":false,"clean":false,"unknownArtist":false,"unknownTitle":false},"junk":[],"warnings":[]}

var back trackparse.Track
err := json.Unmarshal(data, &back)
fmt.Println(err, reflect.DeepEqual(back, track))   // <nil> true
```

The results are plain structs with exported fields. Every result type has a `MarshalJSON` method
that writes the spec's JSON, the same bytes as `JSON.stringify` in JavaScript, so
`encoding/json` needs no struct tags or options. `Track` also has `UnmarshalJSON`, which reads
that JSON back. Nullable fields are pointers (`*Position`, `*int`), and `json.Marshal` writes them
as `null` when they are `nil`.

</TabItem>
</Tabs>

Tracklist results serialize the same way: `JSON.stringify(list)`, `tl.to_dict()`,
`list.to_json()` and `json.Marshal(list)`. See the [Tracklist API](/trackparse/reference/tracklist/).

## Types

<Tabs syncKey="lang">
<TabItem label="JavaScript">

</TabItem>
<TabItem label="Python">

The package ships `py.typed` and passes `mypy --strict`. These are exported from `trackparse`:

- dataclasses: `ParsedTrack`, `Artist`, `Version`, `Junk`, `Flags`, `Position`, `Timestamp`;
- `Literal` aliases: `ArtistRole`, `ArtistSource`, `VersionType`, `VersionDelimiter`, `JunkKind`,
  `Warning`, `Mode`, `ModeOption`;
- `TypedDict`s for options: `ParseOptions`, `KeywordOptions`, `FormatOptions`;
- `Parser`, the class `create_parser` returns.

</TabItem>
<TabItem label="Rust">

All of these are exported from the crate root (`use trackparse::…`):

- structs with public fields: `ParsedTrack`, `Artist`, `Version`, `Junk`, `Flags`, `Position`,
  `Timestamp`;
- enums: `ArtistRole`, `ArtistSource`, `VersionType`, `VersionDelimiter`, `JunkKind`, `Warning`,
  `Mode`. Each has `as_str()` (the spec's name, which `Display` prints too), `from_name()`,
  `FromStr` (its error is `UnknownName`) and `ALL`;
- options: `ParseOptions`, `KeywordOptions`, `FormatOptions`, with the enums `ModeOption`,
  `SplitAnd`, `FeatPlacement`, `JoinerStyle` and `VersionsOption`;
- `Parser`. Every result type has `to_json()`.

```rust
use trackparse::VersionType;

VersionType::SpedUp.as_str();            // "spedUp"
VersionType::from_name("remix");         // Some(Remix)
"bootleg".parse::<VersionType>();        // Ok(Bootleg)
VersionType::ALL.len();                  // 27
```

Most of these enums are `#[non_exhaustive]`, because a later spec version can add a version type or
a warning. A `match` on them needs a `_` arm. The full API is on
[docs.rs](https://docs.rs/trackparse).

</TabItem>
<TabItem label="Go">

All of these are exported from the package (`import "github.com/4matic/trackparse/go"`, package
name `trackparse`):

- structs with exported fields: `Track`, `Artist`, `Version`, `Junk`, `Flags`, `Position`,
  `Timestamp`;
- typed strings: `Role`, `Source`, `VersionType`, `Delimiter`, `JunkKind`, `Warning`, `Mode`. Each
  has a constant per value (`trackparse.RolePrimary`, `trackparse.VersionTypeSpedUp`) and a function
  that returns all values in the spec's order as a new slice (`AllRoles()`, `AllVersionTypes()`). The value is the spec's name,
  so `fmt` prints it as is and a plain conversion reads one;
- options: `ParseOptions`, `Keywords` (with `VersionHead` and `JunkPhrase`), `FormatOptions`,
  with the typed strings `SplitAnd`, `FeatPlacement`, `JoinerStyle` and `VersionsOption`;
- `Parser`, the type `NewParser` returns. Every result type has `MarshalJSON`.

```go
fmt.Println(trackparse.VersionTypeSpedUp)              // spedUp
fmt.Println(trackparse.VersionType("remix") == trackparse.VersionTypeRemix)   // true
fmt.Println(len(trackparse.AllVersionTypes()))         // 27
```

A later spec version can add a version type or a warning, so a `switch` on these needs a
`default` case. The full API is on
[pkg.go.dev](https://pkg.go.dev/github.com/4matic/trackparse/go).

</TabItem>
</Tabs>

[`parsed-track.schema.json`](https://github.com/4matic/trackparse/blob/main/spec/schema/parsed-track.schema.json).
