`parse` never throws on a string. Any string gives a `ParsedTrack`, and unknown or malformed options
fall back to their defaults. (Python raises `TypeError` if `input` isn't a `str` at all. Rust takes
`&str` and never panics.) The options are on the [Options](/trackparse/reference/options/) page.

## ParsedTrack

Every key is always present. Python has the same fields as attributes of a frozen dataclass, in
snake_case (`full_title`, `flags.unknown_artist`), with tuples instead of arrays and `None` instead
of `null`. Rust has a struct with the same snake_case names as public fields: `Vec<T>` for arrays,
`Option<T>` where the table says `null`, enums for `mode`, roles, kinds and warnings, `u32` for
`year` and `position.number`, and `u64` for `timestamp.seconds`.

| Field | Type | Description |
|---|---|---|
| `input` | `string` | The original string, untouched (not normalised) |
| `mode` | `"clean" \| "youtube" \| "filename" \| "tracklist"` | The mode that actually ran |
| `position` | `{ raw: string, number: number } \| null` | Track number. `raw` is the digits as written (`"01"`) |
| `timestamp` | `{ raw: string, seconds: number } \| null` | Leading cue time, `"1:02:03"` → 3723 |
| `artists` | `Artist[]` | Primary, featured and producer credits. Remixers are in `versions` |
| `title` | `string` | The clean title. Brackets it doesn't recognise stay in |
| `fullTitle` | `string` | `title` with the versions put back in their original brackets |
| `versions` | `Version[]` | Remixes and versions, left to right |
| `year` | `number \| null` | From `(2015)` or `- 2015` |
| `flags` | `{ explicit, clean, unknownArtist, unknownTitle }` | All booleans |
| `junk` | `{ raw: string, kind: JunkKind }[]` | What was taken out of the title, and what kind of noise it was |
| `warnings` | `Warning[]` | Which heuristics fired. See [Warnings](/trackparse/reference/warnings/) |

| Field | Values |
|---|---|
| `role` | `primary`, `featured`, `remixer`, `producer` |
| `joiner` | the text before the name as written (`"&"`, `","`, `"ft."`, `"prod. by"`), or `null` for the first name in a list |
| `source` | `artist` (left of the dash), `title` (right of it), `version` (inside a version) |

`&`, `x` and `vs.` are joiners, not roles. Everyone they join is `primary`.

| Field | |
|---|---|
| `type` | one of `remix` `bootleg` `vip` `edit` `flip` `refix` `rework` `mashup` `blend` `dub` `mix` `extended` `radio` `club` `original` `instrumental` `acapella` `live` `acoustic` `remaster` `demo` `reprise` `cover` `version` `spedUp` `slowed` `nightcore` |
| `raw` | the text inside the brackets, as written |
| `artists` | remixers (role `remixer`, source `version`) |
| `modifiers` | type words that didn't become the type: `Extended VIP Mix` → `vip`, `["extended"]` |
| `descriptor` | leftover words: `"Taylor's"`, `"at Wembley"`, `"D'n'B"` |
| `year` | a year inside the version: `Remastered 2015` → 2015 |
| `unknownArtist` | `true` for `ID Remix` and the like |
| `delimiter` | the bracket it was in, or `-` for a dash suffix |

[Versions and remixes](/trackparse/guides/versions/) explains how the type is chosen.

## JSON and Python objects

In JavaScript the result is a plain object, so `JSON.stringify(track)` is the spec's JSON.

In Python, `ParsedTrack`, `Artist`, `Version`, `Junk`, `Flags`, `Position` and `Timestamp` are
frozen dataclasses. Sequences are tuples, so results are immutable and hashable: you can put them in
sets or use them as dict keys. `to_dict()` gives the spec's JSON with its camelCase keys, and
`from_dict()` goes the other way:

```python
import json

json.dumps(track.to_dict(), separators=(",", ":"), ensure_ascii=False)
# the same bytes as JSON.stringify(parse(s)) in JavaScript

ParsedTrack.from_dict(track.to_dict()) == track   # True
```

In Rust the results are plain structs that derive `Debug`, `Clone`, `PartialEq` and `Eq`. Each has
`to_json()`, which writes the spec's JSON as a compact string with no extra dependency. With the
optional `serde` feature the same types implement `Serialize` and `Deserialize`, with the same keys:

```rust
let track = parse(s);

track.to_json()
// the same bytes as JSON.stringify(parse(s)) in JavaScript

// with features = ["serde"]
serde_json::to_string(&track)? == track.to_json()            // true
serde_json::from_str::<ParsedTrack>(&track.to_json())? == track   // true
```

</TabItem>
<TabItem label="Rust">

All of these are exported from the crate root (`use trackparse::…`):

- structs with public fields: `ParsedTrack`, `Artist`, `Version`, `Junk`, `Flags`, `Position`,
  `Timestamp`;
- enums: `ArtistRole`, `ArtistSource`, `VersionType`, `VersionDelimiter`, `JunkKind`, `Warning`,
  `Mode`. Each has `as_str()` (the spec's name, which `Display` prints too), `from_name()`,
  `FromStr` (its error is `UnknownName`) and `ALL`;

  `SplitAnd`, `FeatPlacement`, `JoinerStyle` and `VersionsOption`;
- `Parser`. Every result type has `to_json()`.

</TabItem>
