trackparse never fails, but it does tell you when it had to guess. Warnings are how. There are
three kinds: on a single track, on a tracklist, and on an edit.

In JavaScript and Python a warning code is a string. In Rust it is an enum variant, and `as_str()`
or `Display` gives the same string. The tables below list both.

## Track warnings

`ParsedTrack.warnings` is a list of codes: an array of strings in JavaScript, a tuple of strings in
Python, a `Vec<Warning>` in Rust. An empty list means every decision was unambiguous.

| Warning | Rust | Means | Example |
|---|---|---|---|
| `noSeparator` | `Warning::NoSeparator` | No artist/title separator was found. The whole string is the title | `Around the World` |
| `ambiguousSeparator` | `Warning::AmbiguousSeparator` | A pipe-separated YouTube title had two parts and no dash, so they were read as artist and title | `Noisia \| Stigma` |
| `unspacedDashSplit` | `Warning::UnspacedDashSplit` | Split at a dash without spaces around it (youtube and filename modes, and timed tracklist lines) | `Blink-182-All The Small Things` |
| `asymmetricDashSplit` | `Warning::AsymmetricDashSplit` | Split at a dash with a space on one side only | `Artist -Title` |
| `bySplit` | `Warning::BySplit` | Read `"Title" by Artist` (youtube mode) | `"Numb" by Linkin Park` |
| `quotedTitleSplit` | `Warning::QuotedTitleSplit` | Took a quoted span as the title and what came before it as the artist (youtube mode) | `Linkin Park: "Numb"` |
| `ambiguousMixCredit` | `Warning::AmbiguousMixCredit` | `<Name> Mix` was read as a remix, but the name is long enough that it might be a style | `(Fonetick Lee & Sonic Art Space Drums Mix)` |
| `unbalancedBrackets` | `Warning::UnbalancedBrackets` | A bracket was opened and never closed | `Noisia - Stigma (VIP` |

What to do with them depends on your data. For a music library, a track with any warning is a good
candidate for a human to look at. For scrobbling, most of them are fine to accept.
[Modes](/trackparse/guides/modes/) explains which mode takes which guess. The example below is
[in the playground](/trackparse/playground/#track=Blink-182-All%20The%20Small%20Things&mode=youtube) too.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { parse } from "trackparse";

const track = parse("Blink-182-All The Small Things", { mode: "youtube" });

track.warnings;                                  // [ 'unspacedDashSplit' ]
track.warnings.includes("unspacedDashSplit");    // true
track.warnings.length === 0;                     // false
```

In TypeScript the element type is the union `Warning`, so a misspelled code doesn't compile.

</TabItem>
<TabItem label="Python">

```python
from trackparse import parse

track = parse("Blink-182-All The Small Things", mode="youtube")

track.warnings                           # ('unspacedDashSplit',)
"unspacedDashSplit" in track.warnings    # True
not track.warnings                       # False
```

The element type is the `Literal` alias `Warning`, so mypy catches a misspelled code.

</TabItem>
<TabItem label="Rust">

```rust
use trackparse::{parse_with, ModeOption, ParseOptions, Warning};

let track = parse_with("Blink-182-All The Small Things", &ParseOptions::new().mode(ModeOption::Youtube));

&track.warnings;                                         // [UnspacedDashSplit]
track.warnings.contains(&Warning::UnspacedDashSplit);    // true
track.warnings.is_empty();                               // false

for warning in &track.warnings {
    match warning {
        Warning::NoSeparator => println!("no artist"),
        Warning::UnspacedDashSplit | Warning::AsymmetricDashSplit => println!("check the dash"),
        other => println!("{other}"),   // Display prints the code, such as bySplit
    }
}
// check the dash
```

`Warning` is `#[non_exhaustive]`, so a `match` needs a catch-all arm: a later spec version can add
a warning. `Warning::ALL` lists the variants, and `Warning::from_name("bySplit")` reads a code back.

</TabItem>
</Tabs>

## Tracklist warnings

`Tracklist.warnings` holds objects: `{ code, line, severity, suggestion }`. They are sorted by line.
In Rust the code is a `WarningCode` and the severity is `Severity::Info` or `Severity::Warning`.

| Code | Rust | Severity | When |
|---|---|---|---|
| `time-missing` | `WarningCode::TimeMissing` | warning | A track line has no time while other lines do (not raised on a `w/` line, which plays at the previous track's time) |
| `time-out-of-order` | `WarningCode::TimeOutOfOrder` | warning | Earlier than the previous timed line. May carry a `suggestion` |
| `time-duplicate` | `WarningCode::TimeDuplicate` | warning | Same time as the previous timed line |
| `no-start-at-zero` | `WarningCode::NoStartAtZero` | info | The first time isn't `0:00` |
| `time-after-audio-end` | `WarningCode::TimeAfterAudioEnd` | warning | Later than `audioSeconds` (`audio_seconds`) |
| `invalid-time` | `WarningCode::InvalidTime` | warning | Looks like a time but isn't one (`1:75`, `0:61:00`). The line keeps it in `rest` |
| `position-gap` | `WarningCode::PositionGap` | warning | A track number isn't the previous one plus 1 |
| `position-duplicate` | `WarningCode::PositionDuplicate` | warning | Same track number as the previous one |
| `line-unparsed` | `WarningCode::LineUnparsed` | warning | A track line with no artist/title separator, or nothing after the time |

Warnings of each line's own track stay on `entries[i].track.warnings`. They are the
[track warnings](#track-warnings) above and are not repeated in the list's `warnings`.

The list in this example opens [in the playground](/trackparse/playground/#list=00%3A00%20Noisia%20-%20Stigma%0A04%3A10%20Mefjus%20-%20Sleepless%0A03%3A55%20Phace%20-%20Psycho%0A09%3A30%20Imanu), where both warnings show.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { parseTracklist } from "trackparse/tracklist";

const text = "00:00 Noisia - Stigma\n04:10 Mefjus - Sleepless\n03:55 Phace - Psycho\n09:30 Imanu";
const list = parseTracklist(text);

list.warnings;
// [
//   { code: 'time-out-of-order', line: 3, severity: 'warning', suggestion: null },
//   { code: 'line-unparsed', line: 4, severity: 'warning', suggestion: null }
// ]

list.warnings.filter((w) => w.severity === "warning").map((w) => `line ${w.line}: ${w.code}`);
// [ 'line 3: time-out-of-order', 'line 4: line-unparsed' ]
```

</TabItem>
<TabItem label="Python">

```python
from trackparse.tracklist import parse_tracklist

text = "00:00 Noisia - Stigma\n04:10 Mefjus - Sleepless\n03:55 Phace - Psycho\n09:30 Imanu"
tl = parse_tracklist(text)

tl.warnings
# (TracklistWarning(code='time-out-of-order', line=3, severity='warning', suggestion=None),
#  TracklistWarning(code='line-unparsed', line=4, severity='warning', suggestion=None))

[f"line {w.line}: {w.code}" for w in tl.warnings if w.severity == "warning"]
# ['line 3: time-out-of-order', 'line 4: line-unparsed']
```

</TabItem>
<TabItem label="Rust">

```rust
use trackparse::tracklist::{parse_tracklist, Severity, WarningCode};

let text = "00:00 Noisia - Stigma\n04:10 Mefjus - Sleepless\n03:55 Phace - Psycho\n09:30 Imanu";
let list = parse_tracklist(text);

&list.warnings;
// [TracklistWarning { code: TimeOutOfOrder, line: 3, severity: Warning, suggestion: None },
//  TracklistWarning { code: LineUnparsed, line: 4, severity: Warning, suggestion: None }]

list.warnings.iter()
    .filter(|w| w.severity == Severity::Warning)
    .map(|w| format!("line {}: {}", w.line, w.code))
    .collect::<Vec<_>>();
// ["line 3: time-out-of-order", "line 4: line-unparsed"]

list.warnings.iter().any(|w| w.code == WarningCode::TimeOutOfOrder);   // true
```

`WarningCode` is `#[non_exhaustive]` too, so keep a `_` arm when you `match` on it.

</TabItem>
</Tabs>

Here line 3 has no suggestion, because more than one time would fit between its neighbours. The
checks are [R13.7](/trackparse/reference/spec/#r137-warnings) in the spec, and
[Tracklists](/trackparse/guides/tracklists/#checks) walks through a list that does get a
suggestion.

### Suggestions

A `suggestion` is `{ line, raw, seconds }`: the one time, one or two digits away from what was
written, that puts the list back in order. It's written in the same style as the original.

The search runs in two steps. First it tries the flagged line itself. If no time fits there, it
tries the previous timed line, since sometimes that's where the typo is:
`01:22:21` followed by `01:03:55` suggests changing the first line to `01:02:21`. If more than one
candidate fits, or none does, `suggestion` is `null` (`None` in Python and Rust). A wrong
suggestion would be worse than none.

To apply one, pass its `line` and `seconds` to a `set-time` edit. See
[Editing tracklists](/trackparse/guides/editing-tracklists/).

## Edit warnings

`applyEdits` (`apply_edits` in Python and Rust) returns `{ code, edit, line }` objects. `edit` is
the index in your list of edits, and `line` is `null` (`None`) when the edit names no line.

| Code | Rust | When |
|---|---|---|
| `style-upgraded` | `EditWarningCode::StyleUpgraded` | a time without hours passed one hour and gained them |
| `time-clamped` | `EditWarningCode::TimeClamped` | a time would go below zero and was set to zero |
| `edit-invalid` | `EditWarningCode::EditInvalid` | the edit could not apply and changed nothing |

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { applyEdits } from "trackparse/tracklist";

const result = applyEdits(text, [
  { op: "set-time", line: 9, seconds: 60 },     // there is no line 9
  { op: "shift", seconds: -300, lines: [2] },   // 04:10 minus five minutes
]);

result.warnings;
// [ { code: 'edit-invalid', edit: 0, line: 9 }, { code: 'time-clamped', edit: 1, line: 2 } ]
result.changed;               // [ 2 ]
result.text.split("\n")[1];   // '00:00 Mefjus - Sleepless'
```

</TabItem>
<TabItem label="Python">

```python
from trackparse.tracklist import apply_edits

result = apply_edits(text, [
    {"op": "set-time", "line": 9, "seconds": 60},      # there is no line 9
    {"op": "shift", "seconds": -300, "lines": [2]},    # 04:10 minus five minutes
])

result.warnings
# (EditWarning(code='edit-invalid', edit=0, line=9), EditWarning(code='time-clamped', edit=1, line=2))
result.changed               # (2,)
result.text.split("\n")[1]   # '00:00 Mefjus - Sleepless'
```

</TabItem>
<TabItem label="Rust">

```rust
use trackparse::tracklist::{apply_edits, Edit, EditWarningCode};

let result = apply_edits(text, &[
    Edit::set_time(9, 60.0),           // there is no line 9
    Edit::shift_lines(-300.0, [2]),    // 04:10 minus five minutes
]);

&result.warnings;
// [EditWarning { code: EditInvalid, edit: 0, line: Some(9) }, EditWarning { code: TimeClamped, edit: 1, line: Some(2) }]
result.changed;                  // [2]
result.text.split('\n').nth(1);  // Some("00:00 Mefjus - Sleepless")

result.warnings.iter().any(|w| w.code == EditWarningCode::EditInvalid);   // true
```

</TabItem>
</Tabs>

The first edit changed nothing and the second one still ran: a bad edit never stops the others.
[Editing tracklists](/trackparse/guides/editing-tracklists/#when-an-edit-cant-apply) lists what
makes an edit invalid.
