trackparse never fails, but it does tell you when it had to guess. Warnings are how. There are
three kinds: on a single track, on a tracklist, and on an edit.

In JavaScript and Python a warning code is a string. In Rust it is an enum variant, and `as_str()`
or `Display` gives the same string. In Go it is a constant of a string type, whose value is the
string. In C it is an enum value, and its `_name()` function gives the string. The tables below
give the string and what it means, and each section says once how the Rust, Go and C names are
made from it. The names follow that rule for every code, with no exceptions. Each meaning links
the rule of the [spec](/trackparse/reference/spec/) that raises it.

## Track warnings

`ParsedTrack.warnings` is a list of codes: an array of strings in JavaScript, a tuple of strings in
Python, a `Vec<Warning>` in Rust ([`Warning`](https://docs.rs/trackparse/latest/trackparse/enum.Warning.html)), a `[]Warning` in Go
([`Warning`](https://pkg.go.dev/github.com/4matic/trackparse/go#Warning)), a `const trackparse_warning *` with `warnings_count` in C
([`trackparse.h`](https://github.com/4matic/trackparse/blob/main/c/include/trackparse.h)). An empty list means every decision was unambiguous. Click an example
to open it in the playground.

| Warning | Means | Example |
|---|---|---|
| `noSeparator` | No artist/title separator was found. The whole string is the title ([R6.8](/trackparse/reference/spec/#r6-artisttitle-separator:~:text=R6.8%20No%20separator)) | [`Around the World`](/trackparse/playground/#track=Around%20the%20World) |
| `ambiguousSeparator` | A pipe-separated YouTube title had two parts and no dash, so they were read as artist and title ([R2.4](/trackparse/reference/spec/#r2-mode-prelude:~:text=R2.4%20youtube%20pipes)) | [`Noisia \| Stigma`](/trackparse/playground/#track=Noisia%20%7C%20Stigma&mode=youtube) |
| `unspacedDashSplit` | Split at a dash without spaces around it (youtube and filename modes, and timed tracklist lines: [R6.7](/trackparse/reference/spec/#r6-artisttitle-separator:~:text=R6.7%20Unspaced%20dash), [R6.10](/trackparse/reference/spec/#r6-artisttitle-separator:~:text=R6.10%20Tracklist%20mode)) | [`Blink-182-All The Small Things`](/trackparse/playground/#track=Blink-182-All%20The%20Small%20Things&mode=youtube) |
| `asymmetricDashSplit` | Split at a dash with a space on one side only ([R6.4](/trackparse/reference/spec/#r6-artisttitle-separator:~:text=R6.4%20Asymmetric%20dash)) | [`Artist -Title`](/trackparse/playground/#track=Artist%20-Title) |
| `bySplit` | Read `"Title" by Artist` (youtube mode, [R6.6](/trackparse/reference/spec/#r6-artisttitle-separator:~:text=R6.6%20by%20%28youtube%20only%29)) | [`"Numb" by Linkin Park`](/trackparse/playground/#track=%22Numb%22%20by%20Linkin%20Park&mode=youtube) |
| `quotedTitleSplit` | Took a quoted span as the title and what came before it as the artist (youtube mode, [R6.5](/trackparse/reference/spec/#r6-artisttitle-separator:~:text=R6.5%20Quoted%20title)) | [`Linkin Park: "Numb"`](/trackparse/playground/#track=Linkin%20Park%3A%20%22Numb%22&mode=youtube) |
| `ambiguousMixCredit` | `<Name> Mix` was read as a remix, but the name is long enough that it might be a style ([R5.7](/trackparse/reference/spec/#r5-group-classification:~:text=R5.7%20Version)) | [`(Fonetick Lee & Sonic Art Space Drums Mix)`](/trackparse/playground/#track=Artist%20-%20Title%20%28Fonetick%20Lee%20%26%20Sonic%20Art%20Space%20Drums%20Mix%29) |
| `unbalancedBrackets` | A bracket was opened and never closed ([R3.3](/trackparse/reference/spec/#r3-group-scanner-and-skeleton:~:text=R3.3%20An%20opener)) | [`Noisia - Stigma (VIP`](/trackparse/playground/#track=Noisia%20-%20Stigma%20%28VIP) |

In the other languages the name is the code with its first letter capitalized, after a prefix:
`Warning::` in Rust, `Warning` in Go (`trackparse.WarningNoSeparator`). In C the code is written
in upper case with an underscore between its words, after `TRACKPARSE_WARNING_`
(`TRACKPARSE_WARNING_NO_SEPARATOR`).

What to do with them depends on your data. For a music library, a track with any warning is a good
candidate for a human to look at. For scrobbling, most of them are fine to accept.
[Modes](/trackparse/guides/modes/) explains which mode takes which guess. The example below is
[in the playground](/trackparse/playground/#track=Blink-182-All%20The%20Small%20Things&mode=youtube) too.

<TabItem label="Rust">

```rust
use trackparse::{parse_with, ModeOption, ParseOptions, Warning};

let track = parse_with("Blink-182-All The Small Things", &ParseOptions::new().mode(ModeOption::Youtube));

&track.warnings;                                         // [UnspacedDashSplit]
track.warnings.contains(&Warning::UnspacedDashSplit);    // true
track.warnings.is_empty();                               // false

for warning in &track.warnings {
    match warning {
        Warning::NoSeparator => println!("no artist"),
        Warning::UnspacedDashSplit | Warning::AsymmetricDashSplit => println!("check the dash"),
        other => println!("{other}"),   // Display prints the code, such as bySplit
    }
}
// check the dash
```

`Warning` is `#[non_exhaustive]`, so a `match` needs a catch-all arm: a later spec version can add
a warning. `Warning::ALL` lists the variants, and `Warning::from_name("bySplit")` reads a code back.

</TabItem>

```go
import (
	"fmt"
	"slices"
	"strings"

	"github.com/4matic/trackparse/go"

track := trackparse.ParseWith("Blink-182-All The Small Things", trackparse.ParseOptions{Mode: trackparse.ModeYouTube})

fmt.Println(track.Warnings)                                                         // [unspacedDashSplit]
fmt.Println(slices.Contains(track.Warnings, trackparse.WarningUnspacedDashSplit))   // true
fmt.Println(len(track.Warnings) == 0)                                               // false

for _, warning := range track.Warnings {
	switch warning {
	case trackparse.WarningNoSeparator:
		fmt.Println("no artist")
	case trackparse.WarningUnspacedDashSplit, trackparse.WarningAsymmetricDashSplit:
		fmt.Println("check the dash")
	default:
		fmt.Println(warning)   // the code itself, such as bySplit
	}
}
// check the dash
```

`Warning` is a string type, so a warning prints as its code and compares with the constants
(`trackparse.WarningBySplit`). Keep a `default` case: a later spec version can add a warning.
`trackparse.AllWarnings()` lists the codes.

## Tracklist warnings

`Tracklist.warnings` holds objects: `{ code, line, severity, suggestion }`
([`TracklistWarning`](/trackparse/reference/tracklist/#tracklistwarning)). They are sorted by line.
In Rust the code is a [`WarningCode`](https://docs.rs/trackparse/latest/trackparse/tracklist/enum.WarningCode.html) and the severity is
[`Severity`](https://docs.rs/trackparse/latest/trackparse/tracklist/enum.Severity.html)`::Info` or `Severity::Warning`. In Go they are a
[`WarningCode`](https://pkg.go.dev/github.com/4matic/trackparse/go#WarningCode) and [`SeverityInfo`](https://pkg.go.dev/github.com/4matic/trackparse/go#SeverityInfo) or `SeverityWarning`,
and `Suggestion` is a pointer. In C they are a `trackparse_tracklist_warning_code` and
`TRACKPARSE_SEVERITY_INFO` or `TRACKPARSE_SEVERITY_WARNING`, and `suggestion` is a pointer. All of them are
[R13.7](/trackparse/reference/spec/#r137-warnings) in the spec.

The names drop the dashes and capitalize each word after a prefix: `WarningCode::` in Rust
(`WarningCode::TimeOutOfOrder`), `WarningCode` in Go (`trackparse.WarningCodeTimeOutOfOrder`). In
C the dashes become underscores, in upper case, after `TRACKPARSE_TL_`
(`TRACKPARSE_TL_TIME_OUT_OF_ORDER`).

| Code | Severity | When |
|---|---|---|
| `time-missing` | warning | A track line has no time while other lines do (not raised on a `w/` line, which plays at the previous track's time) |
| `time-out-of-order` | warning | Earlier than the previous timed line. May carry a `suggestion` |
| `time-duplicate` | warning | Same time as the previous timed line |
| `no-start-at-zero` | info | The first time isn't `0:00` |
| `time-after-audio-end` | warning | Later than [`audioSeconds`](/trackparse/guides/tracklists/#options) (`audio_seconds`, `AudioSeconds`) |
| `invalid-time` | warning | Looks like a time but isn't one (`1:75`, `0:61:00`). The line keeps it in `rest` |
| `position-gap` | warning | A track number isn't the previous one plus 1 |
| `position-duplicate` | warning | Same track number as the previous one |
| `line-unparsed` | warning | A track line with no artist/title separator, or nothing after the time |

Warnings of each line's own track stay on `entries[i].track.warnings`. They are the
[track warnings](#track-warnings) above and are not repeated in the list's `warnings`.

The list in this example opens [in the playground](/trackparse/playground/#list=00%3A00%20Noisia%20-%20Stigma%0A04%3A10%20Mefjus%20-%20Sleepless%0A03%3A55%20Phace%20-%20Psycho%0A09%3A30%20Imanu), where both warnings show.

### Suggestions

A `suggestion` is `{ line, raw, seconds }`: the one time, one or two digits away from what was
written, that puts the list back in order. It's written in the same style as the original.

The search runs in two steps. First it tries the flagged line itself. If no time fits there, it
tries the previous timed line, since sometimes that's where the typo is:
`01:22:21` followed by `01:03:55` suggests changing the first line to `01:02:21`. If more than one
candidate fits, or none does, `suggestion` is `null` (`None` in Python and Rust, `nil` in Go, `NULL` in C). A wrong
suggestion would be worse than none.

To apply one, pass its `line` and `seconds` to a `set-time` edit. See
[Editing tracklists](/trackparse/guides/editing-tracklists/). In the
[playground](/trackparse/playground/#list=48%3A20%20Noisia%20-%20Stigma%0A01%3A07%3A44%20Imanu%20-%20Sacrifice%0A00%3A11%3A02%20Current%20Value%20-%20Payload%0A01%3A15%3A36%20Hybris%20-%20Spinning%20Top),
a warning with a suggestion has a button that applies it.

## Edit warnings

[`applyEdits`](/trackparse/reference/tracklist/#applyeditstext-edits-options) (`apply_edits` in Python and Rust, `ApplyEdits` in Go, `trackparse_apply_edits` in C) returns `{ code, edit, line }`
objects ([`EditWarning`](https://docs.rs/trackparse/latest/trackparse/tracklist/struct.EditWarning.html) in Rust,
[`EditWarning`](https://pkg.go.dev/github.com/4matic/trackparse/go#EditWarning) in Go, `trackparse_edit_warning` in C). `edit` is the index in your list of edits, and `line` is
`null` (`None`, `nil` in Go, `NULL` in C) when the edit names no line. The rules are
[R13.9](/trackparse/reference/spec/#r139-edits).

The names follow the tracklist codes with another prefix: `EditWarningCode::` in Rust
(`EditWarningCode::EditInvalid`), `EditWarningCode` in Go
(`trackparse.EditWarningCodeEditInvalid`) and `TRACKPARSE_EDIT_WARNING_` in C
(`TRACKPARSE_EDIT_WARNING_EDIT_INVALID`), of the enum `trackparse_edit_warning_code`.

| Code | When |
|---|---|
| `style-upgraded` | a time without hours passed one hour and gained them ([R13.9.2](/trackparse/reference/spec/#r139-edits:~:text=R13.9.2%20Time%20style)) |
| `time-clamped` | a time would go below zero and was set to zero ([R13.9.3](/trackparse/reference/spec/#r139-edits:~:text=R13.9.3%20Clamp)) |
| `edit-invalid` | the edit could not apply and changed nothing ([R13.9.6](/trackparse/reference/spec/#r139-edits:~:text=R13.9.6%20Totality)) |

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { applyEdits } from "trackparse/tracklist";

const result = applyEdits(text, [
  { op: "set-time", line: 9, seconds: 60 },     // there is no line 9
  { op: "shift", seconds: -300, lines: [2] },   // 04:10 minus five minutes
]);

result.warnings;
// [ { code: 'edit-invalid', edit: 0, line: 9 }, { code: 'time-clamped', edit: 1, line: 2 } ]
result.changed;               // [ 2 ]
result.text.split("\n")[1];   // '00:00 Mefjus - Sleepless'
```
