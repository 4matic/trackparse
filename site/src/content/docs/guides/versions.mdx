A version is anything that says which take of a song this is: a remix, a VIP, a radio edit, a live
recording, a remaster, a sped-up TikTok cut. trackparse reads them from brackets and from dash
suffixes, and puts each one in `versions`, left to right.

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```ts
{
  type: VersionType;          // 'remix', 'vip', 'radio', …
  raw: string;                // the text as written, without brackets: 'Sub Focus VIP Remix'
  artists: Artist[];          // remixers, role 'remixer'
  modifiers: VersionType[];   // other type words that didn't win: [ 'extended' ]
  descriptor: string | null;  // leftover words: "Taylor's", 'at Wembley'
  year: number | null;
  unknownArtist: boolean;     // 'ID Remix'
  delimiter: "(" | "[" | "{" | "-";
}
```

</TabItem>
<TabItem label="Python">

```python
Version(
    type: VersionType,               # 'remix', 'vip', 'radio', …
    raw: str,                        # the text as written, without brackets: 'Sub Focus VIP Remix'
    artists: tuple[Artist, ...],     # remixers, role 'remixer'
    modifiers: tuple[str, ...],      # other type words that didn't win: ('extended',)
    descriptor: Optional[str],       # leftover words: "Taylor's", 'at Wembley'
    year: Optional[int],
    unknown_artist: bool,            # 'ID Remix'
    delimiter: VersionDelimiter,     # "(" | "[" | "{" | "-"
)
```

</TabItem>
<TabItem label="Rust">

```rust
pub struct Version {
    pub version_type: VersionType,     // Remix, Vip, Radio, …
    pub raw: String,                   // the text as written, without brackets: "Sub Focus VIP Remix"
    pub artists: Vec<Artist>,          // remixers, role Remixer
    pub modifiers: Vec<String>,        // other type words that didn't win: ["extended"]
    pub descriptor: Option<String>,    // leftover words: "Taylor's", "at Wembley"
    pub year: Option<u32>,
    pub unknown_artist: bool,          // "ID Remix"
    pub delimiter: VersionDelimiter,   // Paren | Square | Curly | Dash
}
```

</TabItem>
<TabItem label="Go">

```go
type Version struct {
    Type          VersionType  // VersionTypeRemix, VersionTypeVIP, VersionTypeRadio, …
    Raw           string       // the text as written, without brackets: "Sub Focus VIP Remix"
    Artists       []Artist     // remixers, role RoleRemixer
    Modifiers     []string     // other type words that didn't win: ["extended"]
    Descriptor    *string      // leftover words: "Taylor's", "at Wembley"
    Year          *int
    UnknownArtist bool         // "ID Remix"
    Delimiter     Delimiter    // DelimiterParen | DelimiterSquare | DelimiterCurly | DelimiterDash
}
```

</TabItem>

`title` never includes versions. `fullTitle` (`full_title` in Python and Rust, `FullTitle` in Go) is the title with them
put back, in their original brackets.

In Rust the type is the field `version_type`, because `type` is a reserved word, and its values are
enum variants (`VersionType::Remix`, `VersionType::SpedUp`). `as_str()` gives the names used on this
page (`"remix"`, `"spedUp"`), and so does `Display`. `modifiers` holds those names as strings.
`delimiter` is the enum `VersionDelimiter`: `Paren`, `Square`, `Curly` or `Dash`.

In Go the field is `Type`, of the string type `VersionType`. Its constants
(`trackparse.VersionTypeRemix`, `trackparse.VersionTypeSpedUp`) hold the names used on this page, so
they print as `remix` and `spedUp`. `Delimiter` is a string type too, holding the delimiter itself:
`trackparse.DelimiterParen` is `"("`. `Descriptor` and `Year` are pointers, `nil` when absent.

## The 27 types

| Group | Types |
|---|---|
| Rework by someone else | `remix` `bootleg` `vip` `edit` `flip` `refix` `rework` `mashup` `blend` `dub` `mix` |
| Length and format | `extended` `radio` `club` `original` `instrumental` `acapella` |
| Recording | `live` `acoustic` `remaster` `demo` `reprise` `cover` `version` |
| Speed | `spedUp` `slowed` `nightcore` |

The keywords behind them are in
[`version-keywords.json`](https://github.com/4matic/trackparse/blob/main/spec/data/version-keywords.json).
In Rust, `VersionType::ALL` lists the 27 variants and `VersionType::from_name("spedUp")` reads a
name back. In Go, `trackparse.AllVersionTypes` lists them, and since the type is a string,
`trackparse.VersionType("spedUp")` is a conversion.

## Generic words borrow their meaning

"Mix", "Edit" and "Version" don't say much on their own. trackparse looks at the word in front
([R5](/trackparse/reference/spec/#r5-group-classification) in the spec). Click an input to open it
in the playground:

| Input | `type` | Why |
|---|---|---|
| [`(Radio Edit)`](/trackparse/playground/#track=%28Radio%20Edit%29) | `radio` | "Radio" decides; "Edit" is generic |
| [`(Extended Mix)`](/trackparse/playground/#track=%28Extended%20Mix%29) | `extended` | same idea |
| [`(Levela Mix)`](/trackparse/playground/#track=%28Levela%20Mix%29) | `remix`, by Levela | a name before "Mix" means a remix by that name |
| [`(Extended VIP Mix)`](/trackparse/playground/#track=%28Extended%20VIP%20Mix%29) | `vip`, modifiers `[extended]` | the strongest word wins, the rest become modifiers |
| [`(Taylor's Version)`](/trackparse/playground/#track=%28Taylor%27s%20Version%29) | `version`, descriptor `"Taylor's"` | nothing to borrow, so the words are kept as a descriptor |


## Several versions

Two groups give two versions. So does a slash inside one group:

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
parse("Avicii - Levels (Skrillex Remix) [Radio Edit]").versions.map((v) => v.type);
// [ 'remix', 'radio' ]

parse("Dimension - Offshore (Mefjus Remix / Noisia Remix)").versions.map((v) => v.artists[0].name);
// [ 'Mefjus', 'Noisia' ]
```

</TabItem>
<TabItem label="Python">

```python
[v.type for v in parse("Avicii - Levels (Skrillex Remix) [Radio Edit]").versions]
# ['remix', 'radio']

[v.artists[0].name for v in parse("Dimension - Offshore (Mefjus Remix / Noisia Remix)").versions]
# ['Mefjus', 'Noisia']
```

</TabItem>
<TabItem label="Rust">

```rust
parse("Avicii - Levels (Skrillex Remix) [Radio Edit]")
    .versions.iter().map(|v| v.version_type).collect::<Vec<_>>();
// [Remix, Radio]

parse("Dimension - Offshore (Mefjus Remix / Noisia Remix)")
    .versions.iter().map(|v| &v.artists[0].name).collect::<Vec<_>>();
// ["Mefjus", "Noisia"]
```

</TabItem>
<TabItem label="Go">

```go
for _, v := range trackparse.Parse("Avicii - Levels (Skrillex Remix) [Radio Edit]").Versions {
    fmt.Println(v.Type)
}
// remix
// radio

for _, v := range trackparse.Parse("Dimension - Offshore (Mefjus Remix / Noisia Remix)").Versions {
    fmt.Println(v.Artists[0].Name)
}
// Mefjus
// Noisia
```

## Dash suffixes

Streaming services often write versions after a second dash. Those are read too, and the
delimiter is `-` (`VersionDelimiter::Dash` in Rust, `trackparse.DelimiterDash` in Go):

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
const t = parse("The Beatles - Hey Jude - Remastered 2015");
t.title;        // 'Hey Jude'
t.versions[0];  // { type: 'remaster', raw: 'Remastered 2015', year: 2015, delimiter: '-', … }
```

</TabItem>
<TabItem label="Python">

```python
t = parse("The Beatles - Hey Jude - Remastered 2015")
t.title        # 'Hey Jude'
t.versions[0]  # Version(type='remaster', raw='Remastered 2015', ..., year=2015, ..., delimiter='-')
```

</TabItem>
<TabItem label="Rust">

```rust
let t = parse("The Beatles - Hey Jude - Remastered 2015");
&t.title;        // "Hey Jude"
&t.versions[0];  // Version { version_type: Remaster, raw: "Remastered 2015", year: Some(2015), delimiter: Dash, .. }
```

</TabItem>
<TabItem label="Go">

```go
t := trackparse.Parse("The Beatles - Hey Jude - Remastered 2015")
fmt.Printf("%q\n", t.Title)            // "Hey Jude"
v = t.Versions[0]
fmt.Println(v.Type, *v.Year, v.Delimiter)   // remaster 2015 -
fmt.Printf("%q\n", v.Raw)              // "Remastered 2015"
```

</TabItem>
</Tabs>

A dash suffix that isn't a version stays in the title. In a
[tracklist](/trackparse/guides/tracklists/#tracklist-mode) the rule is stricter, because there the
first dash is almost always the separator. The suffix rules are part of
[R6](/trackparse/reference/spec/#r6-artisttitle-separator).

## Unknown remixers

`(ID Remix)` is a remix by someone not yet announced. You get the version with
`unknownArtist: true` (`unknown_artist` in Python and Rust, `UnknownArtist` in Go) and no artists. There is no artist
called "ID". [Unknown artists](/trackparse/guides/artists/#unknown-artists) has an example.

## Your own words

If your catalog uses a word trackparse doesn't know, add it with `keywords.versionHeads` (`version_heads` in Python, `KeywordOptions::version_head` in Rust, `Keywords.VersionHeads` in Go):

<Tabs syncKey="lang">
<TabItem label="JavaScript">

```js
import { createParser } from "trackparse";

const parser = createParser({ keywords: { versionHeads: { rerub: "rework" } } });
parser.parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)").versions[0].type;
// 'rework'
```

</TabItem>
<TabItem label="Python">

```python
from trackparse import create_parser

parser = create_parser(keywords={"version_heads": {"rerub": "rework"}})
parser.parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)").versions[0].type
# 'rework'
```

</TabItem>
<TabItem label="Rust">

```rust
use trackparse::{KeywordOptions, ParseOptions, Parser, VersionType};

let keywords = KeywordOptions::new().version_head("rerub", VersionType::Rework);
let parser = Parser::new(&ParseOptions::new().keywords(keywords));
parser.parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)").versions[0].version_type;
// Rework
```

</TabItem>
<TabItem label="Go">

```go
parser := trackparse.NewParser(trackparse.ParseOptions{
    Keywords: trackparse.Keywords{
        VersionHeads: []trackparse.VersionHead{{Key: "rerub", Type: trackparse.VersionTypeRework}},
    },
})
fmt.Println(parser.Parse("Chase & Status x Camo & Krooked - Track (Alix Perez Rerub)").Versions[0].Type)
// rework
```

</TabItem>
</Tabs>

Keywords only add to the built-in vocabulary. They can't remove words. See
[Options](/trackparse/reference/options/#keywords).
